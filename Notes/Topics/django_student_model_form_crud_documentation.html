2. Create the Student Model

The model defines the database structure.

student_app/models.py
from django.db import models

class StudentModel(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField()
    email = models.EmailField(unique=True)

    def __str__(self):
        return self.name
FieldPurpose
nameStores the student name, up to 100 characters.
ageStores the age as an integer.
emailStores an email and prevents duplicate values with unique=True.
__str__()Controls the readable text representation of the object.
After changing the model: run python manage.py makemigrations and python manage.py migrate.
3. Create a Django ModelForm

A ModelForm creates form fields from a model and gives us validation and saving support.

student_app/forms.py
from django import forms
from .models import StudentModel

class StudentForm(forms.ModelForm):
    class Meta:
        model = StudentModel
        fields = ['name', 'age', 'email']

    def clean_age(self):
        age = self.cleaned_data.get('age')

        if age < 18:
            raise forms.ValidationError(
                'Invalid age, age should be greater than 18'
            )

        return age

Why clean_age()?

It adds custom validation. If the submitted age is below 18, Django marks the form invalid.

Small correction: Since age < 18 is rejected, a clearer message is "Age should be 18 or greater."

6. Build the Views
6.1 Create Student
def create_student(request):
    if request.method == 'POST':
        form = StudentForm(request.POST)

        if form.is_valid():
            form.save()
            return redirect('all_students')
    else:
        form = StudentForm()

    return render(
        request,
        'create_student.html',
        {'form': form}
    )
Why request.POST? It contains the values submitted by the user. Because no existing instance is supplied, form.save() creates a new object.
6.2 Read All Students
def all_students(request):
    students = StudentModel.objects.all()

    return render(
        request,
        'all_students.html',
        {'students': students}
    )
6.3 Edit / Update Student
def edit_student(request, pk):
    Student = get_object_or_404(StudentModel, pk=pk)

    if request.method == "POST":
        form = StudentForm(
            request.POST,
            instance=Student
        )

        if form.is_valid():
            form.save()
            return redirect('all_students')
    else:
        form = StudentForm(instance=Student)
        return render(
            request,
            'create_student.html',
            {'form': form}
        )

6.4 Delete Student
def delete_student(request, pk):
    student = get_object_or_404(StudentModel, pk=pk)

    if request.method == 'POST':
        student.delete()
        return redirect('all_students')
Why POST? Delete changes server-side data. A normal GET link should generally be safe/read-only, so POST is preferred for an intentional delete action.
6.5 Read One Student
def get_student(request, pk):
    student = get_object_or_404(StudentModel, pk=pk)

    return render(
        request,
        'student_detail.html',
        {'student': student}
    )

8. Key Concepts to Remember
StudentForm(request.POST)
"Here is the data the user submitted."
StudentForm(instance=student)
"Use this existing student to populate the form."
StudentForm(request.POST, instance=student)
"Take the submitted data and apply it to this existing student."
form.save()
No instance → create a new object.
With instance → update that existing object.
get_object_or_404() → get object or 404.
render() → show a template.
redirect() → go to another URL.
9. Interview Tips
Q: Why use ModelForm?
A: It creates form fields from a model and provides validation and save support, reducing manual form code.
Q: Why pass request.POST?
A: It contains the values submitted by the user and makes the form a bound form.
Q: Why pass instance=student?
A: It tells Django which existing model object should be displayed and updated.
Q: What is the difference?
StudentForm(request.POST) → normally create a new object.
StudentForm(request.POST, instance=student) → update an existing object.
Q: Why use POST for delete?
A: Delete changes server-side data. GET should generally be safe/read-only.
Q: Why redirect after successful POST?
A: It gives the browser a fresh GET request and avoids accidental form resubmission on refresh. This is commonly called Post → Redirect → Get (PRG).
