CLASS 5

Django File & Folder Structure

Understand each important Django file and folder using very simple, child-friendly examples.

1. First: What Are Files and Folders?

Think about a school bag 🎒

Imagine your Django project is a school bag.

🎒 Django Project │ ├── 📁 Folders → boxes that organize related things └── 📄 Files → papers containing information or instructions

A folder keeps related things together. A file contains information, settings, or instructions that Python and Django can use.

Simple idea: A Django project is a collection of files and folders. Each one has a job.
What is Django?

Django is a Python web framework.

Think of a framework as a ready-made building kit. It gives us useful tools, files, and rules so we do not have to build everything from zero.

Python → Django → Tools + rules + structure → Web application

2. Django Project Structure

Example: project named mysite

After running django-admin startproject mysite, the basic structure is similar to:

mysite/ │ ├── manage.py │ └── mysite/ ├── __init__.py ├── asgi.py ├── settings.py ├── urls.py └── wsgi.py

After Python runs code, you may also see __pycache__ folders.

As the project grows: You may also have db.sqlite3, Django app folders, migrations/, templates/, static/, and other files.
Why do we see mysite twice?
mysite/ ← outer project folder │ ├── manage.py │ └── mysite/ ← inner Python package ├── settings.py ├── urls.py └── ...

The outer folder is mainly a container for the project. The inner folder contains the main Python package and configuration files.

3. Important Django Files

__init__.py
What is it?

A special Python file used for package initialization. It can contain code that should run when the package is initialized.

Child-friendly example 👦

Imagine a classroom has a sign on its door saying:

🚪 “This folder is a Python package.”
Remember: In a normal new Django project, you usually do not need to add anything here.
settings.py
What is it?

This file contains the main configuration of the Django project.

Child-friendly example ⚙️

Think of it as the project's control room. It tells Django things such as installed apps, database settings, middleware, templates, static files, language, and time zone.

🏠 Project → ⚙️ settings.py → “How should this project behave?”
Easy memory: settings.py = project configuration.
urls.py
What is it?

It contains URL patterns that tell Django which code should handle a requested URL.

Child-friendly example 🗺️

Imagine a school map:

🏫 School ├── Room 101 → Maths ├── Room 102 → Science └── Room 103 → English

urls.py works like a map for website URLs: it helps Django decide where a request should go.

Easy memory: urls.py = URL map / traffic controller.
manage.py
What is it?

A command-line helper for working with your Django project.

Child-friendly example 🧰

Think of it as a remote control for common Django tasks.

python manage.py runserver python manage.py makemigrations python manage.py migrate python manage.py createsuperuser

Each command asks Django to perform a particular job.

wsgi.py
Full form

WSGI = Web Server Gateway Interface

What is it?

It provides an entry point for WSGI-compatible web servers to communicate with a Django application.

Child-friendly example 📞
🌐 Web Server ↓ 🗣️ WSGI ↓ 🐍 Django Application

Think of it as a communication bridge between a compatible web server and the Django application.

Easy memory: wsgi.py = WSGI server entry point.
asgi.py
Full form

ASGI = Asynchronous Server Gateway Interface

What is it?

It provides an entry point for ASGI-compatible servers and supports asynchronous application features.

Child-friendly example 🚦
🌐 Web Server ↓ 🚦 ASGI ↓ 🐍 Django Application ↓ Asynchronous features can be supported

Think of ASGI as a flexible communication bridge designed for modern asynchronous web application needs.

Easy memory: asgi.py = ASGI server entry point.

4. __pycache__ Folder

__pycache__
What is it?

Python can automatically create this folder to store bytecode cache files for Python modules.

Child-friendly example 🧠

Imagine you read a difficult lesson and make quick notes so you can work with it more easily later.

Python source code ↓ Python prepares bytecode ↓ __pycache__/ ↓ Cached .pyc files

These cached files can help Python avoid repeating some work when importing modules.

Do not worry about it: You normally do not create this folder yourself. Python creates it when needed, and it can be recreated after deletion.

5. How These Files Work Together

A simple request story

Suppose a user opens http://127.0.0.1:8000/.

👤 User ↓ 🌐 Browser ↓ 📍 URL request ↓ urls.py ↓ Django finds the matching code ↓ 🐍 Django application ↓ 📄 Response ↓ 🌐 Browser

settings.py provides project configuration. manage.py helps you perform project commands. wsgi.py and asgi.py provide server entry points.

Other items you may see later
ItemSimple explanation
db.sqlite3A SQLite database file commonly used in development.
app_name/A Django application folder for a particular feature or part of the website.
migrations/Usually inside an app; stores files describing database schema changes.
templates/A common place for HTML templates.
static/A common place for CSS, JavaScript, and image files.

Interview Tip 💡

If asked about the Django project structure, explain each file by its job: settings.py for configuration, urls.py for URL routing, manage.py for commands, wsgi.py/asgi.py for server entry points, __init__.py for package initialization, and __pycache__ for Python's cached bytecode.
