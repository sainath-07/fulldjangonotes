Class 37 — Django Authentication

What will we learn?

Authentication is the process of checking who the user is. In this class we build a simple Django authentication system with registration, login, logout, and a protected dashboard.

Main idea: Django already provides many authentication tools. We use User, UserCreationForm, authenticate(), login(), logout(), @login_required, and request.user.
REGISTER | v Create User | v login(request, user) | v DASHBOARD LOGIN | v authenticate() | +---- invalid ----> Error | +---- valid ------> login() | v DASHBOARD LOGOUT | v logout() | v LOGIN PAGE
1. What Is Authentication?

Authentication answers the question:

“Who are you?”

For example, when you enter a username and password, Django checks whether those credentials belong to a valid user.

Authentication vs Authorization
ConceptSimple questionExample
AuthenticationWho are you?Login with username/password.
AuthorizationWhat are you allowed to do?Only staff users can open an admin page.
Memory trick: Authentication = identity. Authorization = permission.

4. Registration — Create a New User
accounts/forms.py
from django import forms
from django.contrib.auth.models import User
from django.contrib.auth.forms import UserCreationForm

class RegistrationForm(UserCreationForm):
    email = forms.EmailField(required=True)

    class Meta:
        model = User
        fields = [
            'username',
            'email',
            'password1',
            'password2'
        ]

    def clean_email(self):
        email = self.cleaned_data.get('email')

        if User.objects.filter(email=email).exists():
            raise forms.ValidationError(
                'Email already exists'
            )
        else:
            return email
Why extend UserCreationForm?

UserCreationForm already provides the normal username/password user-creation behavior and password validation. We extend it to add a required email field and our own email uniqueness check.

Custom email validation
def clean_email(self):
    email = self.cleaned_data.get('email')

    if User.objects.filter(email=email).exists():
        raise forms.ValidationError('Email already exists')

    return email
Important: This checks whether another user already has the same email in the database.
Registration view
def register_view(request):
    if request.method == "POST":
        form = RegistrationForm(request.POST)

        if form.is_valid():
            user = form.save()
            login(request, user)
            messages.success(
                request,
                'Registration successful'
            )
            return redirect('dashboard')
        else:
            print("Form errors:", form.errors)
            messages.error(
                request,
                'Registration failed, please correct the below fields'
            )
    else:
        form = RegistrationForm()

    return render(
        request,
        'accounts/register.html',
        {'form': form}
    )
Interesting point: After registration, the code immediately calls login(request, user). Therefore the newly registered user is automatically logged in.
5. Login — Verify Credentials
def login_view(request):
    if request.method == "POST":
        username = request.POST.get('username', '')
        password = request.POST.get('password', '')

        user = authenticate(
            request,
            username=username,
            password=password
        )

        if user is not None:
            login(request, user)
            messages.success(
                request,
                'Login successful'
            )
            return redirect('dashboard')
        else:
            messages.error(
                request,
                'Invalid credentials'
            )
            return render(
                request,
                'accounts/login.html'
            )

    return render(request, 'accounts/login.html')
Understand authenticate()
user = authenticate(
    request,
    username=username,
    password=password
)

Django checks the credentials using its authentication system.

If authentication succeeds, authenticate() returns a user object. If it fails, it returns None.

username + password | v authenticate() | +---+---+ | | user None | | v v login() error | v dashboard
Important distinction: authenticate() checks the credentials. login() actually logs the authenticated user into the current session.
6. Logout — End the Session
def logout_view(request):
    logout(request)

    messages.success(
        request,
        'You have logged out successfully'
    )

    return redirect('login')

The logout() function logs the current user out.

Simple memory: login() starts the authenticated session state; logout() ends it.
7. Protecting the Dashboard
from django.contrib.auth.decorators import login_required

@login_required(login_url='login')
def dashboard_view(request):
    return render(
        request,
        'accounts/dashboard.html'
    )
What does @login_required do?

It checks whether the current user is authenticated before allowing the view to run.

Request /dashboard/ | v @login_required | authenticated? / \ NO YES | | v v redirect view runs to login | v dashboard
Memory trick: @login_required means “You must be logged in to enter this view.”
What is request.user?

9. Complete Authentication Flow
DJANGO AUTHENTICATION | +-------------------+-------------------+ | | | v v v REGISTER LOGIN LOGOUT | | | v v v RegistrationForm authenticate() logout() | | | v +---+---+ v form.save() | | LOGIN | valid invalid | v | | v User object v v message | login() error v | login() v | DASHBOARD v DASHBOARD
Registration flow: Form → validation → save user → login user → dashboard.
Login flow: Username/password → authenticate → if user exists → login → dashboard.
Logout flow: logout → success message → login page.
10. Important Authentication Concepts
Session

A session lets Django remember that a user has authenticated across multiple requests.

Password handling

Django's authentication system is designed to store passwords securely rather than as plain text. You should never manually store plain-text passwords.

Why not manually compare passwords?

Do not write logic such as if password == database_password. Let Django's authentication framework handle password verification.

Why use Django's built-in User?

It provides a ready authentication foundation including usernames, password handling, permissions, groups, and related authentication behavior.

Product-development lesson: Prefer a mature framework's authentication system instead of inventing your own password/session system unless you have a very specific, well-understood requirement.
11. Common Mistakes
  1. Using authenticate(request, name=...) instead of the correct credential keyword such as username=... for the default authentication setup.
  2. Calling login() without first checking the result of authenticate().
  3. Forgetting {% csrf_token %} in POST forms.
  4. Forgetting @login_required on a view that should be private.
  5. Trying to read user information before understanding request.user.
  6. Storing passwords manually or as plain text.
  7. Forgetting to include the correct URL names used by redirect() and template {% url %}.
  8. Confusing authentication with authorization.
Interview tip: When explaining Django authentication, clearly separate these steps: authenticate() verifies identity, login() creates the logged-in session state, and @login_required protects a view.
12. Interview Questions & Answers
Q1. What is authentication?

Authentication is the process of verifying the identity of a user.

Q2. What does authenticate() do?

It checks the supplied credentials using Django's authentication system. A successful authentication returns a user object; failure returns None.

Q3. What is the difference between authenticate() and login()?

authenticate() verifies the credentials. login() associates the authenticated user with the current session.

Q4. What does logout() do?

It logs the current user out and clears the authentication state associated with the session.

Q5. What does @login_required do?

It prevents anonymous users from directly accessing a protected view and redirects them to the login URL when configured.

Q6. What is request.user?

It represents the current user associated with the request. For an anonymous visitor, Django uses an anonymous-user representation.

Q7. Why use UserCreationForm?

It provides a convenient foundation for creating users and handling password-related validation according to Django's authentication conventions.

Q8. How can you add an email field to user registration?

Extend UserCreationForm, declare an email form field, include it in Meta.fields, and add validation such as clean_email() if required.

Q9. Authentication vs authorization?

Authentication determines who the user is. Authorization determines what that user is allowed to access or perform.

Q10. Why should passwords not be stored as plain text?

Plain-text passwords expose users directly if the database is compromised. Passwords should be handled by Django's secure password hashing system.

🎯 Interview-ready answer

“Django provides a built-in authentication framework. For registration I can use UserCreationForm and save a User. During login, authenticate() verifies the credentials and returns a user or None. If authentication succeeds, login() associates that user with the session. logout() ends the logged-in state. For private pages, I use @login_required, and inside a request I can access the current user through request.user.”
