Python, pip, Django & Virtual Environments

A simple, practical guide to installing Python tools and creating isolated project environments.

1. Install Python, pip & Django

Step 1 — Install Python

Download and install Python from the official Python website.

Important: During Windows installation, make sure you select “Add Python to PATH”. This makes the python command available in Command Prompt.

When Python is installed normally, pip is also included with modern Python installations.

Step 2 — Understand pip

pip is Python's package installer. Think of it like npm for Node.js.

Node.js → npm → install JavaScript packages Python → pip → install Python packages

For example, Django is a Python package/framework, so we can install it using pip.

Step 3 — Install Django

Use this command in Command Prompt or PowerShell:

pip install django

General pattern:

pip install <package-name>

2. Check Whether Python, pip & Django Are Installed

Useful verification commands
What you want to check Command What it tells you
Python python --version Shows the installed Python version.
pip pip --version Shows the installed pip version and location.
Installed packages pip list Shows Python packages installed in the current environment.
Django version django-admin --version Shows the installed Django version.
Correction to remember: pip list Django is not the normal command for checking Django. Use pip list and look for Django, or use django-admin --version for the Django version.

3. Virtual Environments

What is a virtual environment?

A virtual environment is a separate Python space for one project.

Think of it like giving every project its own toolbox.

Project A └── .venv └── Django 4.x Project B └── .venv └── Django 5.x Each project can have its own packages and versions.
Why use it? One project's packages do not need to interfere with another project's packages.
Two ideas to keep separate

There are two different things people often mix up:

  1. Installing the virtualenv tool globally: you install the virtualenv package so the command is available on your machine.
  2. Creating a virtual environment for a project: you run the command inside a project's root folder, creating an environment folder for that project.
Important: Installing virtualenv globally does not mean one environment is shared by every project. The environment itself can be created separately for each project.
A. Install the virtualenv tool (installing virtualenv globally)
1
Open Command Prompt or PowerShell.
2
Install the tool:
pip install virtualenv

This installs the virtualenv command/tool so you can create environments.

B. Create an environment inside a project (using virutal environment tool to create environment for specific project)
1
Go to your project root folder.
2
Create an environment with a meaningful name:
virtualenv myproject_venv
Naming tip: For most projects, .venv is a clean and common name. If you need a more descriptive name, use something like blog_venv or ecommerce_venv.
3
Activate it on Windows:
myproject_venv\Scripts\activate
4
When activated, your terminal usually shows the environment name at the beginning.
(myproject_venv) C:\Projects\myproject>
5
Deactivate it when finished:
deactivate
6
To delete the environment, first deactivate it and then remove its folder.
rmdir /s /q myproject_venv

5. Remember This

Common confusion
Don't confuse these two:

pip install virtualenv → installs the tool used to create virtual environments.
virtualenv myproject_venv → creates an actual environment for a project.
Interview Tip 💡

If an interviewer asks why we use virtual environments, say: “A virtual environment isolates a project's Python packages and versions, so different projects can use different dependencies without conflicting with each other.”

Simple mental model
Python ↓ pip = package installer ↓ Django = Python framework/package ↓ virtualenv = tool to create isolated environments ↓ .venv / project_venv = isolated environment for one project
