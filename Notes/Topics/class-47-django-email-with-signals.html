Sending Mail with Django Signals

Automatically send a welcome email after a new Django super user is created.

Goal: Create a Django signal that listens for a newly created User. When the user is created, Django automatically sends an email to that user's email address.
1. What Are We Building?
Definition

Django signals allow one part of a Django application to react automatically when something happens somewhere else. Here, we listen for the post_save event of Django's built-in User model.

Layman example: Think of a shop counter. When a customer completes registration, a staff member automatically gets a notification to send a welcome message. The registration event triggers another action without the registration code having to call the email function directly.
Our requirement
  1. Use Django's predefined User model.
  2. Create a super user.
  3. Provide the email address of the person who should receive the message.
  4. When the user is successfully created, the post_save signal detects it.
  5. If the user is newly created, Django sends the welcome email automatically.
2. Django User Model and Database Setup
1. We are using Django's predefined User model

The code imports:

from django.contrib.auth.models import User

We are not creating our own user model in this example. Django already provides the User model.

2. Do we need makemigrations?
For this class: No. We have not created or changed our own model, so there is no new model migration to generate. Run the existing Django migrations with: 
python manage.py migrate

The important idea is: makemigrations creates migration files for changes to your models. migrate applies available migrations to the database. Django's built-in authentication migrations are already provided by Django.

3. Create the super user
python manage.py createsuperuser

Django asks for details such as username, email address, and password. Enter the email address of the person who should receive the welcome email.

3. Understanding post_save Signal
What is post_save?

post_save is a Django model signal that runs after a model's save() operation completes.

Why do we use created?

The created argument tells us whether this save created a new database row.

Key idea: The if created: check prevents a welcome email from being sent every time the existing user is saved or updated.
4. Complete signals.py Code

Create a new signals.py file inside your blog_app package.

from django.db.models.signals import post_save
from django.dispatch import receiver
from django.contrib.auth.models import User
from django.core.mail import send_mail
from django.core.mail import BadHeaderError
import smtplib


@receiver(post_save, sender=User)
def send_welcome_email(sender, instance, created, **kwargs):
    if created:
        print(f"New user created: {instance.username}")

        subject = 'welcome to mohit kumar'
        message = f'Hi {instance.username}, thank you for registering'
        from_email = 'sainathb308@gmail.com'
        recipient_list = [instance.email]

        try:
            send_mail(
                subject,
                message,
                from_email,
                recipient_list,
                fail_silently=False
            )

            print('Welcome email sent successfully.')

        except BadHeaderError:
            print('Invalid header found in email.')

        except smtplib.SMTPAuthenticationError:
            print(
                'SMTP authentication failed. '
                'Check EMAIL_HOST_USER and EMAIL_HOST_PASSWORD.'
            )

        except Exception as e:
            print(f'Failed to send welcome email: {str(e)}')
Important security note: Do not hard-code real email passwords or SMTP secrets inside signals.py. Keep credentials in environment variables or a secure settings mechanism.
5. Register the Signal in apps.py

Creating signals.py is not enough. Django must import the signals when the application starts.

from django.apps import AppConfig


class BlogConfig(AppConfig):
    name = 'blog'

    def ready(self):
        import blog.signals
        # appname.signals
Why? The ready() method runs when Django initializes the application. Importing blog.signals registers the receiver with Django's signal system.

7. Email Backend Configuration

The signal calls send_mail(), but Django still needs an email backend configuration to know how to deliver the message.

A typical SMTP configuration looks like this conceptually:

EMAIL_BACKEND = 'django.core.mail.backends.smtp.EmailBackend'

EMAIL_HOST = 'smtp.example.com'
EMAIL_PORT = 587
EMAIL_USE_TLS = True

EMAIL_HOST_USER = 'your-email@example.com'
EMAIL_HOST_PASSWORD = 'your-app-password-or-secret'
Do not copy real credentials into source code. Use environment variables for production applications. Also, email providers may require an app password or another authenticated SMTP method.

The exact SMTP host, port, TLS settings, and authentication method depend on the email provider you configure.

8. Code Explained in Simple Words
Import post_save
from django.db.models.signals import post_save

This gives us the signal that runs after a model is saved.

Connect the receiver to User
@receiver(post_save, sender=User)

This says: "Whenever Django saves a User, call this function."

Receive signal information
def send_welcome_email(sender, instance, created, **kwargs):
  • sender → the model that sent the signal.
  • instance → the actual User object that was saved.
  • created → whether this was a new database row.
  • **kwargs → additional signal arguments.
Get recipient email
recipient_list = [instance.email]

The email entered for the user becomes the recipient.

Send email
send_mail(
    subject,
    message,
    from_email,
    recipient_list,

Django's send_mail() function sends the message through the configured email backend.

9. Common Developer Mistakes
1. Wrong import for send_mail
Use from django.core.mail import send_mail, not django.core.email.
2. Typo in **kwargs
Use **kwargs. A spelling such as **kwars is simply incorrect.
3. Typo in message variable
If the variable is named message, pass message to send_mail().
4. Wrong send_mail argument name
The parameter is fail_silently, not fail_silent.
5. Forgetting if created
Without if created:, the email may be sent whenever an existing User is saved too.
6. Forgetting to register/import signals
If blog.signals is never imported during app startup, the receiver may not be registered.
7. Expecting makemigrations for a signal file
Adding signals.py does not create a database model migration. In this class, no custom model was created or changed, so use the existing migrations with migrate.
8. No email backend configuration
A correct signal alone does not guarantee delivery. Django must have a working email backend and SMTP/provider configuration.
9. Hard-coding SMTP secrets
Never put real passwords or API secrets directly in source code.
10. Testing only by reading the code
Actually create a new user and check the application console and recipient inbox. For development, a console email backend can also be useful.
10. If the Email Is Not Sent — Debug Checklist
  1. Check that signals.py is inside the correct app.
  2. Check that the signal is imported in AppConfig.ready().
  3. Check that the app configuration is actually being used by Django.
  4. Check the user's email address is not empty or incorrect.
  5. Check EMAIL_HOST, EMAIL_PORT, TLS/SSL settings, and credentials.
  6. Check the provider's SMTP authentication requirements.
  7. Look at the Django terminal for the printed success/error messages.
  8. Confirm the signal uses sender=User and the receiver is spelled correctly.
Development tip: You can use Django's console email backend during development so emails are printed to the terminal instead of being delivered to a real mailbox.
11. How I Would Explain This to the Interviewer

"Here I am using Django's built-in User model, so I don't need to create a new model for this requirement. I first apply the existing database migrations using python manage.py migrate. Then I create a super user using createsuperuser and provide the recipient's email address. I created a separate signals.py file and connected Django's post_save signal to the User model. The receiver gets the saved User instance and the created flag. I check if created so the welcome email is sent only when a new user is created, not when an existing user is updated. Finally, I use Django's send_mail() function with the configured email backend. I also register the signal in the app's ready() method so Django loads the receiver when the application starts."
