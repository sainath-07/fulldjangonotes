Class 40 — Django Search & Filter

What will we build?

In this class, we will build a simple blog page where the user can:

  • Search posts by title or content.
  • Filter posts by category.
  • Use search and category filtering together.
  • Keep the selected search/filter values visible in the form.
Main idea: The browser sends search and filter values as GET parameters. Django reads those values from request.GET and uses them to filter the database QuerySet.
User | | Search: "django" | Category: "tech" v GET /?q=django&category=tech | v Django View | v PostModel.objects.all() | +--> Search title/content | +--> Filter category | v Filtered QuerySet | v Template | v Filtered posts shown to user
1. What is Search and Filter?
Search

Search means finding records based on a keyword.

For example, if the user types django, we can look for posts where the title or content contains the word.

Filter

Filter means narrowing the results using a condition.

For example, the user can select tech and see only posts whose category is tech.

Search

q=django

Find matching text.

Filter

category=tech

Keep only matching category.

Remember: Search and filter are not two completely different database operations. Both can be implemented by adding conditions to a Django QuerySet.
2. How Search & Filter Works
STEP 1 User enters: q = django category = tech | v STEP 2 Browser sends GET request /?q=django&category=tech | v STEP 3 Django reads: request.GET.get('q') request.GET.get('category') | v STEP 4 Start with: PostModel.objects.all() | v STEP 5 Apply search condition | v STEP 6 Apply category condition | v STEP 7 Send final QuerySet to template | v STEP 8 Display matching posts
Memory trick: GET → Read values → Start QuerySet → Add conditions → Render results.
3. Q Objects — Search Multiple Fields

Django's Q object is useful when we need more complex query conditions.

from django.db.models import Q

posts = posts.filter(
    Q(title__icontains=query) |
    Q(content__icontains=query),
)
What does this mean?

It means:

title contains search word OR content contains search word

In database-query terms, the | operator represents OR.

CodeMeaning
Q(...)Build a query condition
|OR
&AND
~NOT
icontainsContains text, case-insensitive
Interview tip: When you hear “search this keyword in title OR content,” think of a Django Q object with |.
4. Understanding icontains
Q(title__icontains=query)

The double underscore separates the field name from the lookup.

title__icontains | | | +--> lookup | +----------> model field

icontains means the field contains the supplied text without requiring an exact case match.

LookupExample idea
exactValue exactly matches
iexactExact match without case sensitivity
containsContains text
icontainsContains text without case sensitivity
startswithStarts with text
endswithEnds with text
Example: Searching for django can match text such as Django Tutorial because icontains is case-insensitive.
5. blog/views.py — Complete Search & Filter Logic
from django.shortcuts import render
from .models import PostModel
from django.db.models import Q

# Create your views here.
def post_list(request):
    query = request.GET.get('q')          # search keyword
    category = request.GET.get('category') # category filter

    posts = PostModel.objects.all()

    # Search using Q objects
    if query:
        posts = posts.filter(
            Q(title__icontains=query) |
            Q(content__icontains=query),
        )

    # Filter by category
    if category:
        posts = posts.filter(category__iexact=category)

    return render(request, 'blog/post_list.html', {
        'posts': posts,
        'query': query,
        'category': category,
    })
Let's break it into small pieces.
Step 1 — Read the search value
query = request.GET.get('q')

If the URL contains ?q=django, then query becomes "django".

Step 2 — Read the category
category = request.GET.get('category')

If the URL contains ?category=tech, then category becomes "tech".

Step 3 — Get all posts
posts = PostModel.objects.all()

This creates the starting QuerySet.

Step 4 — Apply search only when a query exists
if query:
    posts = posts.filter(
        Q(title__icontains=query) |
        Q(content__icontains=query),
    )
Step 5 — Apply category only when a category exists
if category:
    posts = posts.filter(category__iexact=category)
Important: These conditions are independent. If both values are supplied, both filters are applied.
6. Search + Filter Together

Suppose the user searches for django and chooses tech.

query = "django"
category = "tech"

The code effectively builds a query like:

PostModel.objects.all() | v title contains "django" OR content contains "django" | v category equals "tech" | v FINAL RESULTS

Conceptually, the condition is:

(title contains django OR content contains django) AND category is tech
Easy way to remember: Q objects combine the search fields with OR. Separate filter() calls narrow the QuerySet further.

Why use method="get"?

Search and filtering usually do not change database data. GET is useful because the search state can be represented in the URL.

Form | +-- q = django | +-- category = tech | v GET request | v /?q=django&category=tech
Why value="{{query}}"?

It puts the current search value back into the input after the page reloads.

Why use selected?

It keeps the selected category visible after the search.

{% if category == 'tech' %}selected{% endif %}
Small correction: The original template has <h2>{{post.content}}</h2>. Since content is normally body text, using <p> is more suitable semantically.

9. blog/models.py
from django.db import models

class PostModel(models.Model):
    title = models.CharField(max_length=100)
    content = models.TextField()
    category = models.CharField(
        max_length=200,
        blank=True,
        null=True
    )

    def __str__(self):
        return self.title
Fields used by our search/filter
FieldPurposeUsed for
titlePost titleSearch
contentPost bodySearch
categoryPost categoryFilter
Note: Because category allows blank/null values, you may want additional rules in a real application if every post must belong to a category.

12. Why Use GET for Search?
GET is good for searching
  • Search does not normally change database data.
  • Search values can appear in the URL.
  • A user can bookmark or share a search URL.
  • Browser navigation works naturally.
POST is usually for changes
  • Create data.
  • Update data.
  • Delete data.
  • Other operations that change server state.
Do not treat this as an absolute rule: HTTP method choice depends on the operation and application requirements, but GET is the normal and useful choice for read-only search/filter forms.
13. Common Mistakes & Improvements
Mistake 1 — Forgetting to check for an empty value
if query:
    ...

This avoids adding the search condition when there is no search keyword.

Mistake 2 — Using exact matching for normal text search

For keyword search, icontains is often more useful than exact matching.

Mistake 3 — Forgetting to pass values back to the template
'query': query,
'category': category,
Mistake 4 — Forgetting the filter combination

If both search and category are selected, both conditions should be applied.

Mistake 5 — Loading every record into Python first

Prefer QuerySet filtering such as PostModel.objects.filter(...). Let the database perform the filtering instead of fetching all records and manually filtering them in Python.

Performance tip: As data grows, think about database indexes, query performance, pagination and more advanced search solutions when simple icontains searches are no longer enough.
14. Interview Questions & Tips
Q1. How do you get a search value from a GET request in Django?
query = request.GET.get('q')
Q2. Why use Q objects?

Q objects allow us to build complex conditions and combine them using operators such as OR, AND and NOT.

Q3. How do you search in two fields?
Q(title__icontains=query) |
Q(content__icontains=query)
Q4. What does icontains mean?

It checks whether a field contains the given text without requiring a case-sensitive match.

Q5. How do you filter by category?
posts.filter(category__iexact=category)
Q6. Can search and filter be applied together?

Yes. You can apply multiple filters to a QuerySet. In this example, the search conditions are grouped with OR and the category condition narrows those results further.

Q7. Why use GET instead of POST for search?

Search is normally a read-only operation, and GET makes the search state visible in the URL.

Q8. What does & mean in a URL?

It separates query parameters, for example ?q=django&category=tech.

🎯 Interview-ready answer

“For Django search and filtering, I normally read query parameters using request.GET.get(), start with a QuerySet, and conditionally add filters. For searching across multiple fields, I use Q objects with OR conditions. For category filtering, I add another QuerySet filter.”

15. Quick Revision — Remember This Flow
USER | v Search / Filter Form | v GET | v request.GET.get() / \ / \ q category | | v v Q(title...) category__iexact | v Q(content...) | +---- OR ----+ | v Django QuerySet | v Filtered Posts | v Template | v USER
5 things to remember:
  1. request.GET.get() reads query parameters.
  2. Q() helps build complex queries.
  3. | means OR between Q conditions.
  4. icontains is useful for keyword search.
  5. Multiple QuerySet filters can narrow results step by step.
