1. What is Basic Authentication?

Basic Authentication is a simple authentication scheme built into the HTTP protocol. The client sends the username and password with every request, encoded (Base64) inside the Authorization header:

Authorization: Basic base64(username:password)

DRF's rest_framework.authentication.BasicAuthentication class decodes this header, verifies the credentials against Django's user database, and attaches the authenticated user to request.user.

Important: Basic Authentication sends credentials on every single request. It must always be used with HTTPS, otherwise the username/password can be intercepted in plain text (Base64 is encoding, not encryption).
2. What are AllowAny and IsAuthenticated?
Permission Class Meaning Who can access?
AllowAny Removes all access restrictions Anyone — authenticated or not
IsAuthenticated Requires a valid logged-in / verified user Only users who pass authentication
Permission classes decide who can access a view. Authentication classes decide how DRF identifies who the requester is. They work together: Authentication runs first (identifies the user), then Permission checks if that identified user is allowed in.
3. Key Questions Answered
Does IsAuthenticated allow only the GET method without authentication?
No. IsAuthenticated does not give a free pass to any HTTP method — not even GET. It blocks every method (GET, POST, PUT, DELETE, etc.) for unauthenticated requests. A request without valid credentials receives an HTTP 401 Unauthorized response regardless of the method used.
Does AllowAny allow all methods or views to be accessed without any authentication?
Yes. AllowAny permits all HTTP methods on the view it is attached to, with no authentication required at all. It is typically used for public endpoints like a homepage, public listings, or a health-check API.
4. When to Use Basic Authentication
  • Quick internal testing or development environments
  • Server-to-server communication over a secured HTTPS connection
  • Simple APIs where token/session based auth is not yet set up
  • Avoid in production public-facing apps — prefer Token, Session, or JWT authentication for better security and scalability
Basic Authentication sends credentials on every request — always pair it with HTTPS in real deployments.

blog/views.py
from rest_framework.decorators import api_view,permission_classes
from rest_framework.response import Response
from rest_framework.permissions import IsAuthenticated,AllowAny


@api_view(['GET'])
@permission_classes([AllowAny])
def PublicView(request):
    return Response({'messasge': 'This is a public view accessible to everyone.'})

@api_view(['GET'])
@permission_classes([IsAuthenticated])
def PrivateView(request):
    return Response({'message' : f'hello, {request.user.username}. This is a private view accessible  only to authentication users'})
Note: 'DEFAUTL_PERMISSION_CLASSES' in settings.py has a typo (should be DEFAULT_PERMISSION_CLASSES) — kept here exactly as in the original source, but worth fixing in real code so the global default permission actually applies.
7. Interview Tips
1Explain the difference between Authentication and Permission.

Authentication = identifying who the user is. Permission = deciding what that identified (or anonymous) user is allowed to do.

2Be ready to explain why Basic Authentication needs HTTPS.

Base64 is reversible encoding, not encryption — credentials can be decoded instantly if intercepted over plain HTTP.

3Know the default DRF behavior.

If no permission class is set on a view, DRF falls back to the project-wide default in DEFAULT_PERMISSION_CLASSES. A typo in the setting key (as seen above) means DRF silently uses its built-in default (AllowAny) instead.

4Common trick question:

"Does IsAuthenticated allow anonymous GET requests?" — Interviewers ask this to check if you know permission classes apply per-method, not selectively. Answer confidently: No, all methods are blocked equally.

5Mention alternatives.

Be ready to compare Basic Authentication with Token Authentication, Session Authentication, and JWT — and when each is preferred in production.
