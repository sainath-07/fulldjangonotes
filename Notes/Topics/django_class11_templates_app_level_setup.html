Templates — App Level Setup

2. What is an app-level template?

An app-level template is a template stored inside a Django app's templates/ directory.

For example, if a blog app owns a blog page, we can keep its HTML inside that app:

blog/
├── views.py
├── urls.py
└── templates/
    └── blog/
        └── blog.html
Simple idea: Keep the HTML close to the app that owns the feature.
3. What is a project-level template?

A project-level template is stored in a shared template directory at the project root, commonly beside manage.py.

myproject/
├── manage.py
├── myproject/
└── templates/
    └── home.html

Its directory is normally added to TEMPLATES['DIRS'] in settings.py.

Remember: Project-level templates are useful for pages or components shared across the project.
4. App-level vs project-level templates
PointApp-level templateProject-level template
LocationInside an app's templates/Shared templates/ folder near manage.py
DiscoveryUses app template discovery when APP_DIRS=TrueDirectory is normally configured through DIRS
OwnershipUsually belongs to one appUsually shared by the project
Exampleblog/templates/blog/blog.htmltemplates/home.html
Good forBlog, users, products, orders pagesShared layout, common pages, project-wide UI

When should you use which?

Choose app-level
When the template belongs mainly to one app. Example: blog/templates/blog/blog.html.
Choose project-level
When the template is shared across multiple apps. Example: a common home page or project-wide base template.
5. How to create an app-level template
1

Create a Django project

Start with a Django project.

django-admin startproject myproject
cd myproject
2

Create a Django app

Create an app that will contain the feature.

python manage.py startapp blog_app
3

Register the app

Add the app to INSTALLED_APPS in the inner project's settings.py.

INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.messages',

    'blog_app',
]
4

Create the templates folder inside the app

Create a templates directory inside blog_app. A namespace folder such as blog/ is recommended.

blog_app/
└── templates/
    └── blog/
        └── blog.html
Important correction: For app-level templates, you normally do not need to add the app's template directory to DIRS if APP_DIRS=True. DIRS is primarily for additional project-level template directories.
5

Create the view

Import render and return the app-level template.

from django.shortcuts import render

def blogHome(request):
    return render(request, 'blog/blog.html')
6

Create app-level urls.py

Connect the URL to the app view.

from django.urls import path
from . import views

urlpatterns = [
    path("", views.blogHome, name="blogHome"),
]
7

Include app URLs in the project URLs

The root project URLconf includes the app's URLconf using include().

from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("blog/", include("blog_app.urls")),
]
Now visit: /blog/ → project URLconf → blog_app.urls → blogHome → blog/blog.html.

    ├── models.py

    ├── urls.py

        └── blog/
            └── blog.html
Why the extra blog/ folder? It creates a namespace. If several apps have a home.html, Django can distinguish blog/home.html from shop/home.html.
7. Complete code example

A. blog_app/views.py

from django.shortcuts import render

def blogHome(request):
    return render(request, 'blog/blog.html')

B. blog_app/urls.py

from django.urls import path
from . import views

urlpatterns = [
    path("", views.blogHome, name="blogHome"),
]

C. myproject/urls.py

from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("blog/", include("blog_app.urls")),
]

D. myproject/settings.py

TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',

        # For project-level templates:
        'DIRS': [BASE_DIR / "templates"],

        # Finds templates inside installed apps:
        'APP_DIRS': True,

        'OPTIONS': {
            'context_processors': [
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
                'django.contrib.messages.context_processors.messages',
            ],
        },
    },
]

INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.messages',
    'blog_app',
]
Important: In your original example, 'DIRS': [BASE_DIR / "templates"] is valid for a project-level templates folder, but it is not what makes the app-level blog_app/templates/ directory work. APP_DIRS=True handles app template discovery.

9. Common developer mistakes
1. Forgetting to register the app
If the app is not in INSTALLED_APPS, app-based template discovery may not work as expected.
2. Setting APP_DIRS to False
With the normal Django setup, app template discovery relies on APP_DIRS=True.
3. Wrong template path
If the file is templates/blog/blog.html, use render(request, 'blog/blog.html').
4. Forgetting include()
The project URLconf must include the app URLconf when you want URLs managed by the app.
5. Adding app templates to DIRS unnecessarily
When APP_DIRS=True, app templates are discovered automatically. DIRS is for extra template directories such as a project-level folder.
6. Duplicate template names
Using namespaced paths like blog/blog.html reduces collisions between apps.
7. Mixing project and app folders
Do not confuse myproject/templates/ with blog_app/templates/.
8. Wrong URL prefix
If the project uses path("blog/", include(...)), the browser URL begins with /blog/.
