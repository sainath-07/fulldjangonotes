Class 39 — Django Pagination

What will we learn?

In this class, we will learn how to split a large list of blog posts into smaller pages.

Example: If the database has 100 posts, showing all 100 posts on one page is usually not a good user experience. We can show 3, 10, 20, or another suitable number of posts per page.
Database | | 100 Posts v +----------------------+ | Paginator | | 3 posts per page | +----------------------+ | +--> Page 1 → Posts 1-3 +--> Page 2 → Posts 4-6 +--> Page 3 → Posts 7-9 +--> ... +--> Page 34 → Posts 100
1. What Is Pagination?

Pagination means dividing a large set of results into smaller groups called pages.

For example, suppose we have 10 posts and want to show only 3 posts at a time:

PagePosts
Page 11, 2, 3
Page 24, 5, 6
Page 37, 8, 9
Page 410
Simple memory: Pagination = “Break a big list into small pages.”
2. Why Do We Need Pagination?
Better UI

Users do not have to scroll through hundreds or thousands of records.

Less Data Per Page

The page displays a smaller result set instead of one huge list.

Scalability

Pagination is an important technique when applications work with large datasets.

Real-world examples: Search results, product catalogs, blog posts, admin tables, comments, notifications and many other lists commonly use pagination.
3. How Django Pagination Works
STEP 1 Get posts from database | v Post.objects.all().order_by('id') | v STEP 2 Create Paginator | v Paginator(posts, 3) | v STEP 3 Read page number | v request.GET.get('page') | v STEP 4 Ask Paginator for that page | v paginator.get_page(page_number) | v STEP 5 Send page_obj to template | v STEP 6 Template displays only that page
Memory trick: QuerySet → Paginator → Page number → Page object → Template.

5. blog/views.py — Complete Code
from django.shortcuts import render
from django.core.paginator import Paginator
from .models import Post

# Create your views here.
def post_list(request):
    posts = Post.objects.all().order_by('id')

    paginator = Paginator(posts, 3)

    page_number = request.GET.get('page')
    page_obj = paginator.get_page(page_number)

    return render(
        request,
        'blog/post_list.html',
        {'page_obj': page_obj}
    )
Step 1 — Get the posts
posts = Post.objects.all().order_by('id')

This creates a QuerySet containing the posts. order_by('id') gives the results a predictable order based on the ID.

Why order the QuerySet? Pagination works best when the result ordering is stable. Without an explicit ordering, the database is not required to return rows in a particular order.
Step 2 — Create the Paginator
paginator = Paginator(posts, 3)

The second argument means 3 objects per page.

Paginator( all_posts, 3 ) ↓ Page 1 → 3 posts Page 2 → 3 posts Page 3 → 3 posts ...
Step 3 — Read the requested page
page_number = request.GET.get('page')

If the browser visits /?page=2, then:

page_number = "2"
Note: Values read from request.GET are strings. Django's paginator handles the page-number conversion when get_page() is used.
Step 4 — Get the requested Page object
page_obj = paginator.get_page(page_number)

This gives us the Page object for the requested page.

Step 5 — Send it to the template
return render(
    request,
    'blog/post_list.html',
    {'page_obj': page_obj}
)
Important: We send page_obj, not the complete list, to the template.

Previoushas_previousGo to previous page
Nexthas_nextGo to next page

Why do we use conditions? We should not display a Previous link on page 1 or a Next link on the final page.
9. blog/urls.py
from . import views
from django.urls import path

urlpatterns = [
    path('', views.post_list, name='post_list'),
]

The root URL points to the post_list view.

Browser | | / v blog/urls.py | v views.post_list | v Paginator | v post_list.html
Notice: We do not need a separate URL for every page. The same URL handles different page numbers using the GET parameter.

The project-level URL configuration includes the blog application's URLs.

Project URLs | +-- /admin/ --> Django Admin | +-- / --> include('blog.urls') | v post_list view
Remember: The project URL file decides which application receives the request. The blog URL file decides which blog view handles it.

14. Why Use get_page()?
page_obj = paginator.get_page(page_number)

get_page() is convenient because it handles invalid page input more safely than directly calling page().

User requests: ?page=2 | v Valid page | v Return Page 2 User requests: ?page=abc | v Invalid page number | v get_page() handles it | v Returns a suitable page User requests: ?page=9999 | v Page does not exist | v get_page() handles it | v Returns the last available page
Interview point: get_page() is often convenient for user-controlled page numbers because it handles common invalid/out-of-range values gracefully.
15. Pagination vs Showing All Records
Without PaginationWith Pagination
Large result displayed at onceSmall result displayed per page
Can create a long pageCleaner UI
More records rendered at onceFewer records rendered per page
Harder to navigate large listsEasy page navigation
Important performance idea: Pagination improves the amount of data displayed per page, but it does not mean every pagination design automatically makes every database query fast. For very large datasets, query design, indexes and pagination strategy also matter.
16. Common Mistakes
  1. Forgetting to import Paginator.
  2. Forgetting to read the page GET parameter.
  3. Looping through the original posts instead of page_obj.
  4. Forgetting has_next or has_previous checks.
  5. Not using stable ordering for paginated results.
  6. Confusing paginator.num_pages with page_obj.number.
  7. Creating separate URL routes for every page when a GET parameter is enough.
  8. Assuming pagination alone solves all large-dataset performance problems.
Developer rule: Always think about three things: stable ordering, database/query performance, and user navigation.
17. Interview Questions & Answers
Q1. What is pagination?

Pagination is the process of dividing a large collection of results into smaller pages so users can view the data in manageable groups.

Q2. How do you implement pagination in Django?

Import Paginator, create a Paginator with the QuerySet and number of objects per page, read the requested page from GET parameters, and use get_page() to obtain the Page object.

Q3. What does this do?
paginator = Paginator(posts, 3)

It creates a paginator that displays 3 objects per page.

Q4. How do you get the page number from the URL?
page_number = request.GET.get('page')
Q5. What is page_obj?

It is a Django Page object representing the requested page. It can be iterated to display the current page's objects and also provides pagination information.

Q6. How do you check if a next page exists?
page_obj.has_next
Q7. How do you get the next page number?
page_obj.next_page_number
Q8. How do you get the total number of pages?
page_obj.paginator.num_pages
Q9. Why use order_by('id')?

It provides explicit and stable ordering for the QuerySet, which is important when dividing results into pages.

Q10. Why use GET for pagination?

Pagination is normally a read-only operation, so a query parameter such as ?page=2 is a natural way to represent the current page.

🎯 Interview-ready answer

“In Django, I use the Paginator class to divide a QuerySet into pages. I read the page number from request.GET, call get_page(), and pass the resulting page_obj to the template. The template uses has_previous, has_next, and page-number properties to build navigation.”
