Rendering a Page & Saving Form Data

Learn how a Django page is rendered from a view and how submitted form data is saved into a SQLite database using a model.

1. What We Are Building

In this class, we create a simple contact form. A user enters a name and message, submits the form, and Django saves that information in the database.

Main idea: HTML collects the data → Django view receives the data → Model saves the data → SQLite database stores the data.

2. Two Important Tasks
Task 1: Render a page

Django uses a view to return an HTML template to the browser.

def contact_form(request):
    return render(request, 'contact.html')
Task 2: Save submitted data

The view reads values from the POST request and creates a database record using the model.

Contact.objects.create(
    name=name,
    message=message
)
Simple meaning: render() is used to show a page. objects.create() is used here to create and save a model record.

4. Connecting URLs to Views
blog_app/urls.py
from . import views
from django.urls import path

urlpatterns = [
    path('', views.contact_form, name='contact_form'),
    path('submit/', views.submit_contact, name='submit_contact')
]
What happens here?
URL 1: ''

When the app receives its base path, Django calls contact_form(). That view renders the contact page.

URL 2: 'submit/'

When the form is submitted, the request goes to submit_contact().

Why use name? The template can refer to the URL by name instead of hard-coding the URL path: {% url 'submit_contact' %}.

7. Receiving and Saving Submitted Data
The submit_contact() view
def submit_contact(request):
    if request.method == 'POST':
        print(request.POST)

        name = request.POST.get('name')
        message = request.POST.get('message')

        if name and message:
            Contact.objects.create(
                name=name,
                message=message
            )

            return HttpResponse(
                f'Thank you {name} for message'
            )
        else:
            return HttpResponse(
                'Please all fields information'
            )

    else:
        return redirect('contact_form')
Understand each line

Checks whether the request was sent using POST. Form submission uses POST because we are sending data to the server.

request.POST

8. Saving Data into SQLite Database

Django can use SQLite as the database for a development project. When the model is migrated, Django creates the required database table.

Example Contact model

The view expects a model named Contact with fields named name and message.

from django.db import models

class Contact(models.Model):
    name = models.CharField(max_length=100)
    message = models.TextField()

    def __str__(self):
        return self.name

10. Common Mistakes to Avoid
1. Missing name attribute

If an input does not have the expected name, request.POST.get() may not find the value.

2. Forgetting {% csrf_token %}

Django's POST form protection expects the CSRF token in a normal internal form.

3. Forgetting to migrate

If the database table does not exist yet, run makemigrations and migrate.

4. URL name mismatch

The template uses {% url 'submit_contact' %}, so the URL pattern must have name='submit_contact'.
