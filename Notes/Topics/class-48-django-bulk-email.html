Django Class 48

Sending Bulk Email in Django

Learn how to send multiple emails with send_mass_mail() and how to send HTML content and attachments with EmailMultiAlternatives.

Class goal: Understand which Django email API to choose when sending one email, multiple emails, rich HTML email, or email with attachments.
1. What Is Bulk Email?
Definition

Bulk email means sending email messages to multiple recipients instead of sending only one message to one recipient.

Layman example: Imagine a teacher wants to send a welcome message to 500 students. Writing and sending 500 emails manually would be slow. A bulk-email process lets the application send the required messages programmatically.
What we learn in this class
  1. Send multiple messages using send_mass_mail().
  2. Send HTML email content using EmailMultiAlternatives.
  3. Attach files to an email.
  4. Understand when to use send_mail(), send_mass_mail(), and EmailMultiAlternatives.

Simple rule: Use send_mail() for a straightforward email, send_mass_mail() for multiple straightforward messages, and EmailMultiAlternatives when you need HTML alternatives, attachments, headers, or more control.

4. Sending Multiple Emails with send_mass_mail()
Definition

send_mass_mail() is Django's convenience function for sending a collection of email messages in one call.

Layman example: Instead of saying "send this email" three separate times, you prepare three letters and give the batch to the mailroom together.
Message format
message = (
    subject,
    message,
    from_email,
    recipient_list
)

Each message is represented by a tuple containing the subject, body, sender, and recipient list.

Example
message1 = (
    'Welcome user1',
    'Hello user1, welcome to our platform',
    'sainathb308@gmail.com',
    ['shivarajb308@gmail.com']
)

message2 = (
    'Welcome user2',
    'Hello user2, welcome to our platform',
    'sainathb308@gmail.com',
    ['shivaraj1b308@gmail.com']
)

message3 = (
    'Welcome user3',
    'Hello user3, welcome to our platform',
    'sainathb308@gmail.com',
    ['shivaraj2b308@gmail.com']
)

send_mass_mail(
    (message1, message2, message3),
    fail_silently=False
)
Important: The messages can have different subjects, bodies, and recipient lists. send_mass_mail() is useful when the messages are relatively simple.
5. send_mass_mail() — Complete View Code
from django.core.mail import send_mass_mail
from django.http import HttpResponse
from django.core.mail import BadHeaderError
import smtplib


def send_bulk_email(request):

    message1 = (
        'Welcome user1',
        'Hello user1, welcome to our platform',
        'sainathb308@gmail.com',
        ['shivarajb308@gmail.com']
    )

    message2 = (
        'Welcome user2',
        'Hello user2, welcome to our platform',
        'sainathb308@gmail.com',
        ['shivaraj1b308@gmail.com']
    )

    message3 = (
        'Welcome user3',
        'Hello user3, welcome to our platform',
        'sainathb308@gmail.com',
        ['shivaraj2b308@gmail.com']
    )

    try:
        send_mass_mail(
            (message1, message2, message3),
            fail_silently=False
        )

        return HttpResponse(
            'Bulk emails sent successfully!'
        )

    except BadHeaderError:
        return HttpResponse(
            'Invalid header found in email.',
            status=400
        )

    except smtplib.SMTPAuthenticationError:
        return HttpResponse(
            'SMTP authentication failed. '
            'Check EMAIL_HOST_USER and EMAIL_HOST_PASSWORD.',
            status=500
        )

    except Exception as e:
        return HttpResponse(
            f'Failed to send bulk emails: {str(e)}',
            status=500
        )
6. EmailMultiAlternatives — HTML, Attachments and Rich Email
Definition

EmailMultiAlternatives creates an email message object that gives you more control over the email body and attachments.

Layman example: A simple email is like sending a plain letter. EmailMultiAlternatives is like preparing a designed brochure that can contain formatted HTML and an attached document.
What can we do?
  • Send a plain-text fallback.
  • Attach an HTML version of the email.
  • Attach files.
  • Build a richer email message object.
Basic structure
msg = EmailMultiAlternatives(
    subject,
    text_content,
    from_email,
    recipient_list
)

msg.attach_alternative(
    html_content,
    'text/html'
)

msg.send()
7. HTML Email Template

Create:

blog_app/templates/welcome_email.html
<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <meta name="viewport"
          content="width=device-width, initial-scale=1.0">
    <title>Welcome</title>
</head>
<body>
    <h1>{{ username }}</h1>
    <p>Welcome to our platform.</p>
</body>
</html>

The Django template engine replaces {{ username }} with the value supplied by the view.

Example: If the view sends {'username': 'sainath'}, the HTML template can display sainath.
8. EmailMultiAlternatives Complete Example
from django.core.mail import EmailMultiAlternatives
from django.template.loader import render_to_string
from django.http import HttpResponse


def send_bulk_email(request):

    subject = 'Welcome to our platform'

    from_email = 'sainathb308@gmail.com'

    recipient_list = [
        'shivarajb308@gmail.com'
    ]

    html_content = render_to_string(
        'welcome_email.html',
        {'username': 'sainath'}
    )

    msg = EmailMultiAlternatives(
        subject,
        'Welcome to sainath platform',
        from_email,
        recipient_list
    )

    msg.attach_alternative(
        html_content,
        'text/html'
    )

    # Attach a file when required:
    # msg.attach_file('/path/to/file.pdf')

    msg.send()

    return HttpResponse(
        'Email sent successfully'
    )
What is happening? The plain-text body is supplied to EmailMultiAlternatives, then the HTML version is attached as an alternative. Email clients that support HTML can display the HTML version.

Attach file content manually

For more control, Django's email message API can also work with attachment content. A common pattern is:

msg.attach(
    'invoice.pdf',
    file_content,
    'application/pdf'
)

The MIME type should match the file being attached. For example, PDF uses application/pdf. For images, use the appropriate image MIME type.

Security and size reminder: Validate uploaded files and avoid sending unexpectedly large attachments. Email providers can enforce attachment-size and message-size limits.

12. Sending to Around 500 Users — Will Google Charge?

There is no universal answer that "500 emails always cost a fixed amount." The cost and sending limits depend on the email provider, account type, sending method, current provider policies, and whether you are using a personal mailbox, business email service, or dedicated transactional/bulk-email service.

Important: Django itself does not decide the provider's pricing. Django hands the email to the configured backend/provider. The provider determines quotas, limits, authentication requirements, and any charges.
For production bulk email
  • Check the provider's current sending limits and pricing.
  • Do not assume a normal Gmail/Google Workspace mailbox is designed for large-scale marketing campaigns.
  • For application-generated bulk or transactional mail, a dedicated email delivery provider may be more appropriate.
  • Respect provider policies, recipient consent, unsubscribe requirements where applicable, and rate limits.
Interview answer: "The number 500 does not by itself determine the price. I would check the current provider quota and pricing for the specific account and service being used."
13. Common Developer Mistakes
1. Wrong import.
Use from django.core.mail import send_mass_mail. There is no Django function named send_bulk_email to import from django.core.mail.
2. Wrong HttpResponse import.
Use from django.http import HttpResponse.
3. Confusing send_mail and send_mass_mail.
send_mail() is convenient for a single message. send_mass_mail() accepts multiple message tuples.
4. Using send_mass_mail for rich HTML/attachments.
If the email needs HTML alternatives or attachments, use EmailMultiAlternatives.
5. Forgetting attach_alternative().
Rendering an HTML template does not automatically make it the email's HTML body. Attach it with msg.attach_alternative(html_content, 'text/html').
6. Forgetting to call msg.send().
Creating an EmailMultiAlternatives object does not send it by itself.
7. Hard-coding SMTP passwords.
Keep secrets in environment variables or a secure secret-management system.
8. Sending hundreds of messages inside a slow web request.
For real production workloads, consider a background job/queue and a provider designed for bulk delivery.
9. Ignoring provider limits.
Large batches can hit rate limits, quotas, spam controls, or message-size limits.
10. Not validating recipient data.
Clean and validate email addresses before sending. Avoid sending to unintended recipients.
14. How I Would Explain This to the Interviewer

"In this class I learned three Django email approaches. send_mail() is suitable for a simple individual email. send_mass_mail() is useful when I need to send multiple simple messages in one call. When I need a richer email, such as an HTML body or attachments, I use EmailMultiAlternatives. For the bulk-email example, I prepare message tuples and pass them to send_mass_mail(). For the HTML email example, I render a Django template with render_to_string(), create an EmailMultiAlternatives object, attach the HTML version with attach_alternative(), optionally attach a file, and call send(). For production-scale sending, I would also consider provider quotas, rate limits, user consent, and background processing instead of blocking a web request."

Interview tips
  • Do not just memorize method names; explain the requirement each method solves.
  • Remember the key difference: send_mass_mail() is a convenience API for multiple messages, while EmailMultiAlternatives is a richer message object.
  • Explain why HTML email needs attach_alternative().
  • Mention msg.send() when using EmailMultiAlternatives.
  • For 500+ recipients, mention provider quotas and production architecture rather than promising a specific cost.
