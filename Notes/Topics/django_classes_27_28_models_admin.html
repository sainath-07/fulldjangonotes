2. Creating Multiple Models
What is a model?

A Django model is a Python class that describes the data we want to store in the database.

Simple idea: One model normally represents one type of data, such as Student, Profile, Product, or Order.
Example: Student and Profile
from django.db import models

class Student(models.Model):
    name = models.CharField(max_length=100)
    age = models.IntegerField()
    email = models.EmailField(unique=True)

    def __str__(self):
        return self.name


class Profile(models.Model):
    bio = models.TextField(max_length=1000)
    location = models.CharField()
    birth_date = models.DateField(null=True)

    def __str__(self):
        return self.bio

Why use __str__()?

The __str__() method controls the readable name of an object. Django Admin uses it when showing model objects.

def __str__(self):
    return self.name
Important: __str__() must return a string. If the value is a number, convert it with str().
3. Run Migrations After Creating Models

After creating or changing models, Django needs to update the database structure. We do this with migrations.

Step 1 — Create migration files 
python manage.py makemigrations

Django checks your model changes and creates migration instructions.

Step 2 — Apply migrations 
python manage.py migrate

Django applies those instructions to the database.

Correction: The command is python manage.py migrate, not python manage.py run migrate.

4. Registering Models in Django Admin

Registering a model makes it available inside the Django Admin panel.

Method 1 — Simple registration
from django.contrib import admin
from .models import Student, Profile

admin.site.register(Student)
admin.site.register(Profile)
Result: Both Student and Profile appear in the Django Admin panel.
Create an admin user
python manage.py createsuperuser

Django will ask for details such as username, email, and password. Use these credentials to log in to the admin panel.

Start the development server
python manage.py runserver

5. Customizing the Django Admin List View

The default admin list view may not show the fields you want. We can customize it using ModelAdmin.

Example
from django.contrib import admin
from .models import Student, Profile

admin.site.register(Profile)

@admin.register(Student)
class StudentAdmin(admin.ModelAdmin):
    list_display = ('name', 'age', 'email')
    search_fields = ('name', 'age')
    list_filter = ('age', 'name')
    ordering = ('name',)
What does each option do?
OptionPurposeExample
list_displayControls columns shown in the list.('name', 'age', 'email')
search_fieldsAdds a search box for selected fields.('name', 'age')
list_filterAdds filters on the right side.('age', 'name')
orderingSets the default sorting order.('name',)
Easy way to remember: Display = columns, Search = search box, Filter = filter options, Ordering = default sorting.
6. Registering a Model in the New Way

Instead of calling admin.site.register(Student), we can use the @admin.register() decorator.

@admin.register(Student)
class StudentAdmin(admin.ModelAdmin):
    list_display = ('name', 'age', 'email')

The decorator connects the StudentAdmin configuration with the Student model.

Traditional style
class StudentAdmin(admin.ModelAdmin):
    ...

admin.site.register(Student, StudentAdmin)
Decorator style
@admin.register(Student)
class StudentAdmin(admin.ModelAdmin):
    ...
Interview point: Both approaches register the model. The decorator style keeps the registration close to the admin configuration and is easy to read.
7. Adding Filters Using a Tuple

To add multiple filters, provide the model field names inside a tuple.

list_filter = ('age', 'name')

This tells Django Admin to create filter options for the age and name fields.

Why do we use a comma in a one-item tuple?
ordering = ('name',)

In Python, ('name') is just a string inside parentheses. The comma makes it a tuple:

type(('name'))   # str
type(('name',))  # tuple
Remember: Parentheses do not create a tuple by themselves. The comma creates the one-item tuple.
