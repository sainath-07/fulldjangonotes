Project Templates Connect with Apps

Learn how a project-level base template can be extended by an app-level template using Django template inheritance.

Core idea: Project template = common layout   →   App template = page-specific content
1. What We Are Building

In this class, we connect a project-level template with a template inside the blog app.

The project template provides the common page structure. The app template extends that structure and fills the content block.

Remember: {% extends %} connects the child template to the parent template, while {% block %} defines the parts that a child can replace.
2. Create Project & App — Configuration Setup
1Create Django project

Create the main Django project that contains manage.py.

2Create blog app

Create the app that will contain blog-specific views, URLs, and templates.

3Register the app

Add the app to INSTALLED_APPS in settings.py.

Important: For a project-level template, configure the project's template directory in TEMPLATES['DIRS']. Keep the directory name consistent with the folder you actually create.
3. Project Structure

A clean structure makes it easier to understand which template belongs to the project and which belongs to the app.

myproject/ │ ├── manage.py │ ├── myproject/ │ ├── settings.py │ ├── urls.py │ └── ... │ ├── templates/ │ └── index.html │ └── blog/ ├── urls.py ├── views.py └── templates/ └── blog/ └── blog.html
Two template locations:
templates/index.html is the project-level parent template.
blog/templates/blog/blog.html is the app-level child template.
4. settings.py — Tell Django About the Project Template Folder
TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',

        # Project-level templates folder
        'DIRS': [BASE_DIR / 'templates'],

        'APP_DIRS': True,

        'OPTIONS': {
            'context_processors': [
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
                'django.contrib.messages.context_processors.messages',
            ],
        },
    },
]

APP_DIRS = True tells Django to also look for templates inside installed apps, such as blog/templates/.

Key interview point: DIRS is commonly used for project-level template directories, while APP_DIRS=True enables template discovery inside installed apps.
5. Project-Level Template — Parent Template

The parent template contains the common HTML structure. Child templates can reuse it instead of writing the same HTML again.

templates/index.html

<!doctype html>
<html lang="en">
  <head>
    <meta charset="UTF-8" />
    <meta name="viewport" content="width=device-width, initial-scale=1.0" />
    <title>{% block title %} MY title {% endblock %}</title>
  </head>
  <body>
    <h1>MAIN PAGE</h1>
    <hr>

    {% block content %} {% endblock %}

  </body>
</html>
{% block title %}
Creates a replaceable area for the page title.
{% block content %}
Creates a replaceable area for page-specific content.
6. App-Level Template — Child Template

The blog template extends the project template. It does not need to repeat the full HTML document.

7. views.py — Render the App Template

The view receives the browser request and returns the blog template.

from django.shortcuts import render

# Create your views here.
def blogPage(request):
    return render(request, 'blog/blog.html')
Why blog/blog.html?
Because Django can find the app's template directory through APP_DIRS=True, and the template is stored as blog/templates/blog/blog.html.
8. URLs — Connect the App to the Main Project

blog/urls.py

from . import views
from django.urls import path

urlpatterns = [
    path('', views.blogPage, name="blogPage")
]

inner project — myproject/urls.py

from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('', include('blog.urls')),
    path('shop/', include('shop.urls')),
    path('admin/', admin.site.urls),
]

10. Why Use Project + App Templates?
Project-Level TemplateApp-Level Template
Common layoutPage-specific content
Header, footer, main structureBlog page, product page, profile page
Usually reused by many appsUsually belongs to one app
Acts as parent/baseCan act as child using extends
Main benefit: You avoid copying the same HTML layout into every app page. This follows the DRY idea — Don't Repeat Yourself.
11. Common Developer Mistakes
1. Wrong template folder
Creating templates in one location but configuring a different folder in DIRS.
2. Forgetting APP_DIRS
If you rely on app-level templates, make sure APP_DIRS is enabled in the normal Django setup.
3. Wrong extends path
For this structure, the child uses {% extends "index.html" %} because the parent is in the project template directory.
4. Wrong render path
Use render(request, 'blog/blog.html') for the shown app template structure.
5. Forgetting include()
The main project's urls.py must include the app URL configuration.
6. Block name mismatch
If the parent has block content, the child must also use block content to replace it.
