CLASS 15 • DJANGO TEMPLATES

Template Tags

Learn how Django template tags control logic, loops, reusable values, formatting, and HTML escaping.

1. Template Tags — The Big Picture

Template tags are Django instructions written inside {% ... %}. Variables such as {{ name }} mainly display data, while tags tell the template what to do.

View
Python data
→
Template Tags
logic / loops
→
HTML
browser output
TagMain purpose
{% if %}Condition checking
{% for %}Loop through data
{% with %}Store a value in a temporary template variable
{% cycle %}Rotate through values, often useful for rows
{% firstof %}Display the first truthy value
{% now %}Display the current date/time
{% verbatim %}Prevent Django from parsing a template block
{% autoescape %}Turn automatic HTML escaping on or off for a block
Memory: {{ }} is commonly used to display a value. {% %} is used for template instructions.

from datetime import datetime

def blogPage(request):
    blogs = [
        {'title': 'Django basics', 'is_featured': True, 'author': 'Sainath biradar'},

3. {% if %} ... {% else %}

Use if when the template needs to make a decision.

{% if blogs.0.is_featured %}
    <h2>Featured blog: {{ blogs.0.title }}</h2>
{% else %}
    <h2>No featured Blog: {{ blogs.0.title }}</h2>
{% endif %}
Condition
→
True → HTML A
/
False → HTML B
Common mistake: Remember to close the block with {% endif %}.
4. {% for %} ... {% empty %}

Use for to repeat HTML for every item in a list or other iterable.

<ul>
{% for blog in blogs %}
    <li>{{ forloop.counter }}. {{ blog.title }} {{ blog.author }}</li>
{% empty %}
    <li>No blog available</li>
{% endfor %}
</ul>

Useful forloop variables

VariableMeaning
forloop.counterCurrent iteration, starting at 1
forloop.counter0Current iteration, starting at 0
forloop.firstTrue on the first iteration
forloop.lastTrue on the last iteration
forloop.revcounterIterations remaining including current
Why {% empty %}? It gives a useful message when the collection has no items.
5. {% with %}

with assigns a value to a temporary variable. It is useful when an expression is long or reused.

{% with total_blogs=blogs|length %}
    <p>Total Blogs: {{ total_blogs }}</p>
{% endwith %}

Important: The variable created by with is available only inside its block.
6. {% cycle %}

cycle rotates through the values you provide. It is useful inside loops for alternating table-row styles or CSS classes.

{% for blog in blogs %}
<tr style="background-color: {% cycle 'lightblue' 'lightgreen' %};">
    <td>{{ forloop.counter }}</td>
    <td>{{ blog.title }}</td>
</tr>
{% endfor %}

7. {% firstof %}

firstof evaluates values from left to right and displays the first truthy value. It can also use a fallback.

{% firstof blogs.0.author "added" %}
Correction to the supplied example: The context variable is blogs, not blog outside the loop. Use blogs.0.author.
Memory: first available truthy value wins.
8. {% now %}

The now tag displays the current date and/or time using a Django date format string.

{% now "Y-m-d H:i" %}
Example format: 2026-08-30 19:46
Tip: The actual value depends on the current time and Django's configured timezone.
9. {% verbatim %}

Use verbatim when you want Django to leave template-looking syntax untouched. This is useful when showing template syntax as an example.

{% verbatim %}
<p>Author: {{ blog.1.author }}</p>
{% endverbatim %}
Template-looking text
→
verbatim
→
Shown without Django parsing it
10. {% autoescape on/off %}

autoescape controls automatic HTML escaping for variables inside a template block.

Default behavior

In normal Django HTML templates, autoescaping is enabled by default. HTML inside a variable is normally displayed as text rather than interpreted as markup.

<p>Default: {{ html_code }}</p>

Trusted HTML

<p>Trusted HTML: {{ html_code|safe }}</p>

Turn autoescape off for a block

{% autoescape off %}
    <p>{{ html_code }}</p>
{% endautoescape %}
Security warning: Never use |safe or autoescape off blindly with user-provided HTML. It can create XSS vulnerabilities.
HTML in variable
→
Autoescape ON
→

HTML in variable
→

→

Interview memory: Autoescape is a safety feature. safe means you are telling Django to trust the value; it does not sanitize unsafe HTML.

12. Common Developer Mistakes
1. Forgetting closing tags
Close blocks with endif, endfor, endwith, and the correct closing tag.
2. Wrong variable name
The context contains blogs, not blog outside the loop.
3. Confusing tags and filters
{% for %} is a tag. {{ name|upper }} uses a filter.
4. Disabling autoescape carelessly
Do not trust arbitrary user HTML.
5. Too much logic in templates
Keep complex business logic in Python.
6. Misunderstanding firstof
It selects the first truthy value, not merely the first variable that exists.
