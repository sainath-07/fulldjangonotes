Class 38 — Django Image Uploading

What will we learn?

In this class, we will learn how to upload an image from an HTML form, save it using Django, and display the uploaded image on another page.

Big picture: A user selects an image → the browser sends the image → Django receives it through request.FILES → the ModelForm validates and saves it → Django stores the file under the media directory → the template displays it using profile.image.url.
USER | | Select image v HTML FORM | | POST + multipart/form-data v DJANGO VIEW | | request.FILES v MODEL FORM | | form.save() v IMAGE FIELD | v media/profiles/ | v TEMPLATE | | {{ profile.image.url }} v DISPLAY IMAGE
1. What Is Image Uploading in Django?

Image uploading means allowing a user to select an image from their computer or phone and send that file to the Django server.

Django can work with uploaded files through its file and image fields. In this example, the Profile model has an ImageField.

class Profile(models.Model):
    name = models.CharField(max_length=100)
    image = models.ImageField(upload_to="profiles/")
Important: ImageField is designed for image files. Django's image handling also requires the Pillow package.
Where is the uploaded image stored?

The example uses:

MEDIA_ROOT = os.path.join(BASE_DIR, 'media')

Because the model says:

upload_to="profiles/"

an uploaded image will normally be stored inside:

media/profiles/
Memory trick: MEDIA_ROOT = physical storage location. MEDIA_URL = URL prefix used to access uploaded media.
2. MEDIA_URL and MEDIA_ROOT
MEDIA_URL = '/media/'
MEDIA_ROOT = os.path.join(BASE_DIR, 'media')
SettingSimple meaningExample
MEDIA_ROOT Where uploaded files are physically stored on the server. project/media/
MEDIA_URL The URL prefix used to refer to uploaded media. /media/
MEDIA_ROOT | v project/ └── media/ └── profiles/ ├── photo1.jpg ├── photo2.png └── photo3.webp MEDIA_URL | v /media/ | +--> /media/profiles/photo1.jpg
Easy way to remember:
ROOT = Where? → Where is the file stored?
URL = How? → What URL prefix is used to access the file?
Security note: User-uploaded files should be validated and served carefully. In production, media storage is often handled by dedicated storage such as object storage/CDNs rather than Django's development server.
3. Project urls.py — Serve Media During Development
from django.contrib import admin
from django.urls import path, include
from django.conf import settings
from django.conf.urls.static import static

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('accounts.urls'))
]

if settings.DEBUG:
    urlpatterns += static(
        settings.MEDIA_URL,
        document_root=settings.MEDIA_ROOT
    )
Why do we add this?

During development, Django can serve files from MEDIA_ROOT using the configured MEDIA_URL.

Browser requests: /media/profiles/photo.jpg | v MEDIA_URL = /media/ | v MEDIA_ROOT = project/media/ | v media/profiles/photo.jpg | v Browser receives image
Important: This static() setup is intended for development. Production deployments should use an appropriate web server or media storage service for uploaded files.
4. accounts/models.py — ImageField
from django.db import models

    name = models.CharField(max_length=100)
    image = models.ImageField(upload_to="profiles/")

    def __str__(self):
        return self.name
name

Stores the profile name.

image
image = models.ImageField(upload_to="profiles/")

This field stores information about the uploaded image and points to its stored file.

What does upload_to mean?

It tells Django which subdirectory inside MEDIA_ROOT should be used for uploaded files.

MEDIA_ROOT | +-- profiles/ | +-- uploaded_image.jpg
Important: The model does not store the complete image bytes directly in the normal database row. The field stores information such as the file path/name, while the actual file is stored in the configured media storage.
5. accounts/forms.py — ModelForm

class ProfileForm(forms.ModelForm):

6. accounts_app/views.py — Upload View
from django.shortcuts import render, redirect
from .models import Profile
from .forms import ProfileForm
from django.contrib import messages

def upload_profile(request):
    if request.method == "POST":
        form = ProfileForm(request.POST, request.FILES)

        if form.is_valid():
            form.save()
            messages.success(
                request,
                'Profile picture uploaded'
            )
            return redirect('view_profile')
        else:
            messages.error(
                request,
                'Error uploading picture, please try again'
            )
    else:
        form = ProfileForm()

    return render(
        request,
        'upload_profile.html',
        {'form': form}
    )
Step 1 — Check the request method
if request.method == "POST":

A POST request means the user submitted the form.

Step 2 — Pass normal form data and files
form = ProfileForm(request.POST, request.FILES)

This line is extremely important for file uploading.

ArgumentContains
request.POSTNormal submitted form values such as the name.
request.FILESUploaded files such as images.
Common mistake: If you forget request.FILES, the uploaded image will not be passed to the ModelForm correctly.
Step 3 — Validate
if form.is_valid():

Django validates the submitted data before saving it.

Step 4 — Save
form.save()

This creates the Profile record and saves the uploaded file through the model's image field/storage.

Step 5 — Show a success message
messages.success(request, 'Profile picture uploaded')
Step 6 — Redirect
return redirect('view_profile')

After a successful upload, the user is redirected to the profile page.

Good pattern: POST → validate → save → message → redirect. This also follows the common Post/Redirect/Get pattern.
7. Upload View — GET vs POST
User opens /upload/ | v GET request | v form = ProfileForm() | v Show empty upload form User clicks Upload | v POST request | v ProfileForm(request.POST, request.FILES) | v form.is_valid() / \ YES NO | | v v save() show form | v redirect
Memory trick: GET = show the form. POST = process the form.

10. upload_profile.html — The Upload Form
{% extends 'base.html' %}

{% block content %}
<h2>Upload Profile Picture</h2>

<form method="post"
      enctype="multipart/form-data">

    {% csrf_token %}

    {{ form.as_p }}

    <button type="submit">
        Upload
    </button>

</form>
{% endblock %}
The most important part: enctype
enctype="multipart/form-data"

When an HTML form uploads a file, the form must use multipart/form-data.

Interview favorite: A file-upload form needs method="post" and enctype="multipart/form-data".
Why POST?

Uploading a file changes server-side data, so POST is the appropriate HTTP method.

Why multipart/form-data?

It allows the request body to contain file data along with normal form fields.

Why CSRF token?
{% csrf_token %}

Django uses CSRF protection for POST forms. The token helps protect against cross-site request forgery.

Easy memory: POST + multipart/form-data + request.FILES are the three things you should immediately think about when you see Django file upload.

14. Common Mistakes
  1. Forgetting enctype="multipart/form-data" in the HTML form.
  2. Forgetting request.FILES in the ModelForm constructor.
  3. Forgetting to configure MEDIA_ROOT.
  4. Forgetting to configure MEDIA_URL.
  5. Forgetting the development static() media URL configuration.
  6. Trying to display {{ profile.image }} when you actually need the browser URL {{ profile.image.url }}.
  7. Using a GET request for an upload operation.
  8. Forgetting the CSRF token on a POST form.
  9. Trusting uploaded files without proper validation in a production application.
  10. Assuming Django's development media serving configuration is suitable for production.
Most common interview trap: If the interviewer asks why an uploaded image is not arriving in the view, check multipart/form-data and request.FILES first.

16. Interview Questions & Answers
Q1. How do you upload an image in Django?

Use an ImageField in the model, create a form, submit the form using POST with multipart/form-data, pass request.POST and request.FILES to the form, validate it, and save it.

Q2. Why is multipart/form-data required?

It allows the HTTP request body to carry file data together with normal form fields.

Q3. What is request.FILES?

It is Django's collection of uploaded files from the current request.

Q4. What is the difference between MEDIA_ROOT and MEDIA_URL?

MEDIA_ROOT is the filesystem location where uploaded files are stored. MEDIA_URL is the URL prefix used to access those files.

Q5. What does upload_to="profiles/" mean?

It tells Django to store uploaded files in the profiles/ subdirectory of the configured media storage.

Q6. How do you display an uploaded image in a template?
<img src="{{ profile.image.url }}" alt="">
Q7. Why use ImageField instead of a normal CharField?

ImageField is designed for uploaded image files and provides image/file handling through Django's file storage system.

Q8. Why do we use request.POST and request.FILES together?

request.POST contains normal form values, while request.FILES contains uploaded files. An image-upload form can contain both.

Q9. Is Django's static() media configuration enough for production?

No. It is intended for development. Production applications normally use a proper web server and/or dedicated media storage.

Q10. What package is commonly required for Django ImageField?

Django's ImageField requires Pillow for image processing.

🎯 Interview-ready answer

“For image uploading in Django, I use an ImageField with an upload_to directory. The HTML form uses POST and multipart/form-data. In the view, I pass both request.POST and request.FILES to the ModelForm. After validation, form.save() stores the model information and uploaded file using Django's storage system. I configure MEDIA_ROOT and MEDIA_URL, and use image.url in the template to display the uploaded image.”
