Models, Migrations & SQLite

Simple notes to understand how Django stores application data.

1. Introduction to Models

In Django, a model is a Python class that describes the data we want to store in a database. A model usually represents a database table.

Simple meaning: A Django model is a Python representation of a database table.
🐍
Python Class

You define a Django model using a Python class.

→
🗄️
Database Table

Django maps the model to a database table.

Example Model
from django.db import models class Student(models.Model): name = models.CharField(max_length=100) age = models.IntegerField() email = models.EmailField()
How to understand it?
  • Student is the model name.
  • name, age, and email are fields.
  • Each field describes what type of data can be stored.
  • Django uses this model information when creating and working with the database table.
Remember: Model = structure of the data. It tells Django what information your application needs to store.
Interview tip: “In Django, a model is a Python class that represents the structure of data stored in a database.”

2. Create a Model

Suppose we are building a simple student management application. We want to store student information.

1Open models.py

Inside your Django app, open the models.py file.

myproject/ ├── manage.py └── students/ ├── admin.py ├── apps.py ├── models.py ← create model here └── views.py
2Define the Model
from django.db import models class Student(models.Model): name = models.CharField(max_length=100) age = models.IntegerField() email = models.EmailField() def __str__(self): return self.name
3Understand the Fields
FieldMeaning
CharFieldStores text.
IntegerFieldStores whole numbers.
EmailFieldStores email-style text and provides email validation support.
max_length=100Sets the maximum length for the text field.
Important: Creating the model class does not by itself create or change the database table. Django migrations are used to apply model changes to the database.

3. Migration and Migration File

A migration is Django's way of recording changes to your models and applying those changes to the database.

Simple meaning: Model changes → Migration file → Database changes.
Migration Working Flow
1. Change Model
Add or change a field.
→
2. makemigrations
Django creates a migration file.
→
3. migrate
Django applies the change.
→
4. Database
Database structure is updated.
Step 1: Create the Migration File
python manage.py makemigrations

Django checks your models and creates a migration file describing the database changes.

Step 2: Apply the Migration
python manage.py migrate

Django reads the migration files and applies the required changes to the configured database.

What is a Migration File?

A migration file is a Python file stored inside the app's migrations folder. It contains instructions that describe database schema changes.

students/ └── migrations/ ├── __init__.py └── 0001_initial.py
# Example idea of what a migration represents migrations.CreateModel( name="Student", fields=[ ... ], )
Interview tip: makemigrations creates migration files. migrate applies those migrations to the database.

4. Understand SQLite Database

SQLite is a small, file-based relational database. It is commonly used for development, learning, testing, and small applications.

Simple meaning: SQLite stores the database in a file instead of requiring a separate database server.
Typical Django Setup

A new Django project commonly uses SQLite by default. The database is usually stored in a file named db.sqlite3.

Database Configuration

In Django, the database configuration is found in settings.py.

DATABASES = { "default": { "ENGINE": "django.db.backends.sqlite3", "NAME": BASE_DIR / "db.sqlite3", } }
What happens after migration?
  1. You create a model.
  2. You run python manage.py makemigrations.
  3. Django creates migration instructions.
  4. You run python manage.py migrate.
  5. Django updates the SQLite database.
  6. Your application can now store and read data through Django's ORM.
Important: SQLite is a relational database, but it is different from server-based databases such as PostgreSQL and MySQL. For larger or more demanding production systems, a server-based database may be a better fit.
Interview tip: SQLite is lightweight and file-based. It is convenient because a separate database server is not required.

Quick Revision

  • Model: Python class representing data.
  • Field: Defines a piece of data in the model.
  • Migration: Records and applies model/database structure changes.
  • SQLite: Lightweight file-based relational database.

python manage.py makemigrations python manage.py migrate
