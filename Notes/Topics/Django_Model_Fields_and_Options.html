Model Fields & Field Options

A simple, interview-friendly reference for Django model fields and their commonly used options.

1. What is a Model Field?

A model field defines one piece of data stored by a Django model. Django uses the field type to understand what kind of value the field should contain.

class Orders(models.Model): name = models.CharField(max_length=100) weight = models.IntegerField()
Remember: CharField and IntegerField are field classes. max_length is a field option.

2. Text & String Fields

FieldPurposeExample
CharFieldShort or limited-length text.models.CharField(max_length=100)
TextFieldLarge text such as descriptions or articles.models.TextField()
EmailFieldEmail address with email validation support.models.EmailField()
SlugFieldShort URL-friendly text.models.SlugField()
URLFieldURL or web address.models.URLField()

3. Number Fields

FieldPurposeExample
IntegerFieldWhole numbers.models.IntegerField()
BigIntegerFieldLarge whole numbers.models.BigIntegerField()
SmallIntegerFieldSmaller-range whole numbers.models.SmallIntegerField()
PositiveIntegerFieldPositive or zero whole numbers.models.PositiveIntegerField()
PositiveSmallIntegerFieldSmaller-range positive or zero numbers.models.PositiveSmallIntegerField()
PositiveBigIntegerFieldLarge positive or zero whole numbers.models.PositiveBigIntegerField()
FloatFieldFloating-point numbers.models.FloatField()
DecimalFieldFixed-precision decimal values, useful for money.models.DecimalField(max_digits=10, decimal_places=2)
Interview tip: Prefer DecimalField for exact decimal values such as prices. Floating-point values can have representation/rounding issues.

4. Date & Time Fields

FieldPurposeExample
DateFieldStores a date.models.DateField()
DateTimeFieldStores date and time.models.DateTimeField()
TimeFieldStores time.models.TimeField()
created_at = models.DateTimeField(auto_now_add=True) updated_at = models.DateTimeField(auto_now=True)

5. Boolean & Choice Features

FeaturePurposeExample
BooleanFieldStores true/false values.models.BooleanField(default=False)
choicesRestricts a field to predefined values.models.CharField(max_length=20, choices=STATUS_CHOICES)
STATUS_CHOICES = [ ("PENDING", "Pending"), ("SHIPPED", "Shipped"), ("DELIVERED", "Delivered"), ] status = models.CharField( max_length=20, choices=STATUS_CHOICES, default="PENDING" )

6. Special-Purpose Fields

FieldPurposeExample
UUIDFieldStores UUID values.models.UUIDField()
JSONFieldStores JSON-compatible data.models.JSONField(default=dict)
FileFieldStores a file reference/upload.models.FileField(upload_to="files/")
ImageFieldStores an image reference/upload.models.ImageField(upload_to="images/")
Note: ImageField requires Pillow. File/image fields normally store a path or reference in the database while the actual file is handled by Django's configured storage.

7. Relationship Fields

FieldRelationshipExample
ForeignKeyMany-to-one.models.ForeignKey(User, on_delete=models.CASCADE)
OneToOneFieldOne-to-one.models.OneToOneField(User, on_delete=models.CASCADE)
ManyToManyFieldMany-to-many.models.ManyToManyField(Product)
ForeignKey
Customer → Many Orders
OneToOneField

ManyToManyField

Important: ForeignKey and OneToOneField commonly use on_delete to define what happens when the referenced object is deleted.

8. Field Options

OptionMeaningExample
max_lengthMaximum length for fields that support it.max_length=100
null=TrueAllows database NULL.age = models.IntegerField(null=True)
blank=TrueAllows an empty value during Django validation.name = models.CharField(max_length=100, blank=True)
defaultDefault value when one is not supplied.active = models.BooleanField(default=True)
db_defaultDatabase-side default on supported Django versions/databases.models.IntegerField(db_default=0)
unique=TrueRequires values to be unique.email = models.EmailField(unique=True)
primary_key=TrueMakes the field the model's primary key.id = models.UUIDField(primary_key=True)
db_index=TrueCreates a database index.email = models.EmailField(db_index=True)
db_columnSets the database column name.models.CharField(db_column="customer_name", max_length=100)
editable=FalseExcludes the field from ModelForms.models.DateTimeField(editable=False)
help_textHelp text shown by forms/admin.help_text="Enter your full name"
verbose_nameHuman-readable field name.verbose_name="Customer Name"
error_messagesCustom validation error messages.error_messages={"unique":"Already exists."}
validatorsCustom validation functions.validators=[my_validator]
choicesRestricts values to predefined choices.choices=STATUS_CHOICES
auto_nowUpdates a date/time field when the object is saved.models.DateTimeField(auto_now=True)
auto_now_addSets the current time when the object is first created.models.DateTimeField(auto_now_add=True)
null vs blank: null=True is mainly about database storage. blank=True is mainly about Django validation. They are not the same.
Interview tip: Be ready to explain null vs blank, default vs db_default, and unique vs db_index.

9. Complete Example

from django.db import models class Orders(models.Model): name = models.CharField(max_length=100) description = models.TextField(blank=True) weight = models.DecimalField(max_digits=8, decimal_places=2) quantity = models.PositiveIntegerField(default=1) is_delivered = models.BooleanField(default=False) status = models.CharField( max_length=20, choices=[ ("PENDING", "Pending"), ("SHIPPED", "Shipped"), ("DELIVERED", "Delivered"), ], default="PENDING" ) created_at = models.DateTimeField(auto_now_add=True) updated_at = models.DateTimeField(auto_now=True)
Easy rule: Field type = what kind of data? Field option = how should Django/database handle that data?
