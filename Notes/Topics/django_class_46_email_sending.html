Django Email Sending

Learn how Django can send manual, automatic, and bulk emails using SMTP and Django's email utilities.

1. What is Email Sending in Django?
Definition

Django provides built-in email utilities such as send_mail() and EmailMessage to send emails from a Django application. Django normally uses an SMTP email server to deliver the message.

Layman example: Imagine your Django application is a receptionist. The receptionist prepares a message, gives it to a delivery service (SMTP server), and the delivery service sends it to the customer's inbox.

2. Three Types of Email Sending
1. Manual
Manual Email Sending

The email is triggered directly by a developer or a specific request/action.

Example: Click a URL and send a test email.
2. Automatic
Automatic Email Sending

Django sends an email when a predefined event happens.

Example: Send a welcome email after registration.
3. Bulk
Bulk Email Sending

One message or campaign is sent to many recipients.

Example: Send a newsletter to thousands of users.
Important: Manual, automatic, and bulk describe when/how the application triggers emails. SMTP is the delivery mechanism used to communicate with the mail server.
3. Gmail Setup for Manual Email Sending

When using Gmail SMTP, an app password is commonly used instead of putting your normal Gmail password into Django.

1
Enable 2-Step Verification.
Make sure 2-Step Verification is enabled for the Google account.
2
Create an App Password.
Open Google's App Passwords page: https://myaccount.google.com/apppasswords
3
Use the generated app password.
Store it securely. Do not hard-code it into your source code or commit it to Git.
Typical Django SMTP settings
# settings.py

EMAIL_BACKEND = 'django.core.mail.backends.smtp.EmailBackend'
EMAIL_HOST = 'smtp.gmail.com'
EMAIL_PORT = 587
EMAIL_USE_TLS = True
EMAIL_HOST_USER = 'your-email@gmail.com'
EMAIL_HOST_PASSWORD = 'your-app-password'
Security rule: Never expose your real app password in a public GitHub repository. Prefer environment variables or a secrets manager.

5. Manual Email — Text Format
What?

send_mail() is a simple Django helper for sending a plain-text email.

Why?

It is useful when the email only needs simple text and does not require a designed HTML template.

How?

Pass the subject, message, sender, and recipient list to send_mail().

# views.py

from django.shortcuts import render
from django.core.mail import send_mail, BadHeaderError
from django.http import HttpResponse
import smtplib

def send_test_email(request):
    subject = 'Welcome to My Blog'
    message = 'Thank you for subscribing to My Blog'
    from_email = 'your-email@gmail.com'
    recipient_list = ['recipient@gmail.com']

    try:
        send_mail(
            subject,
            message,
            from_email,
            recipient_list
        )
        return HttpResponse('Test email sent successfully')

    except BadHeaderError:
        return HttpResponse(
            'Invalid header found in email.',
            status=400
        )

    except smtplib.SMTPAuthenticationError:
        return HttpResponse(
            'SMTP authentication failed. Check your email settings.',
            status=500
        )

    except Exception as e:
        return HttpResponse(
            f'Failed to send email: {str(e)}',
            status=500
        )
Layman example: subject is the envelope title, message is the letter, from_email is the sender, and recipient_list contains the people receiving the letter.
Important parameters
ParameterPurpose
subjectEmail subject.
messagePlain-text email body.
from_emailEmail address shown as the sender.
recipient_listList of recipient email addresses.
6. Manual Email — HTML Template
Definition

Instead of putting all email content directly into the Python file, you can create an HTML email template and load it with render_to_string().

Layman example: Instead of writing a whole letter inside your Python code, create a nicely designed letter template separately and fill it with the user's name and course information.
View code
from django.core.mail import EmailMessage
from django.http import HttpResponse
from django.template.loader import render_to_string

def send_test_email(request):
    subject = 'Welcome to My Blog'

    message = render_to_string(
        'email/welcome_email.html',
        {
            'username': 'sainath',
            'course': 'django course'
        }
    )

    email = EmailMessage(
        subject,
        message,
        'your-email@gmail.com',
        ['recipient@gmail.com']
    )

    email.content_subtype = 'html'
    email.send()

    return HttpResponse('Test email sent successfully')
Template: templates/email/welcome_email.html
<!DOCTYPE html>
<html>
<body>
  <h2>Welcome {{ username }}!</h2>
  <p>Thank you for joining our {{ course }}.</p>
  <p>We are happy to have you with us.</p>
</body>
</html>
Key line: email.content_subtype = 'html' tells Django that the email body should be treated as HTML rather than plain text.

6

9. Common Developer Mistakes
1. Using the normal Gmail password
With an app-password based setup, use the generated app password rather than exposing the account password.
2. Hard-coding secrets
Do not place real SMTP credentials directly in settings.py when the project is shared or deployed.
3. Forgetting HTML subtype
If using EmailMessage with HTML content, set content_subtype = 'html'.
4. Incorrect SMTP configuration
Check host, port, TLS/SSL configuration, username, and app password.
5. No error handling
SMTP authentication and email delivery can fail. Handle expected exceptions and log useful diagnostic information.
6. Sending bulk mail inside a web request
Large email jobs can make a request slow or time out. In production, background jobs such as Celery are commonly used.
10. How to Explain This in an Interview
30-second answer:
“Django provides built-in email utilities for sending emails through an SMTP backend. For a simple plain-text email, I can use send_mail(). For more control, such as HTML templates or attachments, I can use EmailMessage. With Gmail SMTP, I configure the SMTP host, port, TLS, username, and an app password. I keep credentials outside source control and handle SMTP errors properly.”
Possible interview questions
  1. What is SMTP and why does Django use it?
  2. What is the difference between send_mail() and EmailMessage?
  3. How do you send an HTML email in Django?
  4. Why do you need an app password for some Gmail SMTP setups?
  5. How do you protect email credentials in production?
  6. How would you send an email automatically after user registration?
  7. How would you handle bulk emails without blocking the HTTP request?
  8. What happens if SMTP authentication fails?
Interview tip: Explain the flow instead of only showing code:
Event/Request → View/Service → Email Utility → SMTP Server → Recipient
11. Production Notes
  • Keep SMTP credentials in environment variables or a secrets manager.
  • Do not expose email credentials in GitHub or frontend code.
  • For automatic emails, trigger the email from a well-defined application event.
  • For large bulk-email workloads, use a background task queue rather than keeping the HTTP request waiting.
  • Use an email provider suitable for production volume and delivery requirements.
  • Log failures without logging passwords, tokens, or other secrets.
Important: Gmail's account settings, authentication requirements, sending limits, and availability of app passwords can change. Always verify the current Google account requirements before configuring production email.
