get_object_or_404(), render(), redirect() & Delete

A simple, interview-ready explanation using your Student CRUD example.

Core idea: render() shows a page, redirect() sends the browser to another URL, and get_object_or_404() safely fetches an object or returns a 404 response.
1. What is get_object_or_404()?

Simple meaning

get_object_or_404() tries to find an object in the database.

  • If the object exists → return the object.
  • If it does not exist → return an HTTP 404 response.
student = get_object_or_404(StudentModel, pk=pk)
URL
/students/10/
→
Find Student
pk=10
→
Exists → Object
Doesn't exist → 404
Without it
student = StudentModel.objects.get(pk=pk)

If the object does not exist, .get() raises DoesNotExist.

Remember: get_object_or_404() = Get object OR show 404.
2. What is render()? When do we use it?

Simple meaning

render() is used when Django needs to display an HTML template, optionally with Python data.

return render(
    request,
    'all_students.html',
    {'students': students}
)
What each argument means
ArgumentMeaning
requestThe current HTTP request.
'all_students.html'The HTML template Django should display.
{'students': students}Context data passed from Python to the template.
Python View

Example from your code
def all_students(request):
    students = StudentModel.objects.all()
    return render(
        request,
        'all_students.html',
        {'students': students}
    )
Use render when: you want to display a page/form/template for the current request.
3. What is redirect()? When do we use it?

Simple meaning

redirect() tells the browser to make a request to another URL/view.

return redirect('all_students')
Current View
→
redirect()
→
Another URL / View
Your create flow
if form.is_valid():
    form.save()
    return redirect('student_success')

After saving the student, you don't want to render the create form again. You send the user to the success page.

Important: After a successful POST that changes data, redirecting is a common pattern called Post → Redirect → Get (PRG).

5. Why edit uses <a> but delete uses <form>?

Edit link

<a href="{% url 'edit_student' student.id %}">
    Edit student details
</a>

Clicking the link makes a GET request. In your application, GET only opens the edit form.

Click Edit
→
GET
→
Show Edit Form

Delete form

<form method="post"
      action="{% url 'delete_student' student.id %}">
    {% csrf_token %}
    <button type="submit">Delete</button>
</form>

Delete changes the database, so your application uses a POST request for the destructive action.

Click Delete
→
POST
→
Find Student
→
Delete → Redirect
Why not delete with a normal <a> link?
A normal anchor sends GET. GET should generally be safe/read-only, not perform destructive database operations. A crawler, prefetcher, or accidental visit should not delete a record.

Can an anchor still trigger delete?

Technically, you can build a delete action around a link using JavaScript or other mechanisms, but simply using a normal GET link is not a good design for deletion.

For a beginner Django CRUD application, a POST form with CSRF protection is the clean and standard approach.

6. Understanding your delete_student() view 
def delete_student(request, pk):
    student = get_object_or_404(StudentModel, pk=pk)

    if request.method == "POST":
        student.delete()
        return redirect("all_students")

    return redirect("all_students")
Step-by-step
  1. Get the student using the primary key.
  2. If the student doesn't exist, return 404.
  3. Check that the request is POST.
  4. Delete the student.
  5. Redirect back to the students list.
Correction in your original code:
{'students': student} passes one Student object, while your template expects students to be a collection used by {% for student in students %}. Also, there is normally no need to render the list again from the delete view.

8. Interview Tips
Q: What does get_object_or_404() do?
A: It retrieves an object and returns a 404 response if the object does not exist.
Q: What is the difference between render() and redirect()?
A: render() returns an HTML template for the current request, while redirect() tells the browser to go to another URL.
Q: Why use POST for delete instead of GET?
A: Deletion changes server-side data. GET should generally be safe and should not perform destructive actions.
Q: Why is {% raw %}{% csrf_token %}{% endraw %} present in the delete form?
A: It provides CSRF protection for the POST request.
