Templates - Project Level Setup

Learn what templates are, how Django finds them, and how to connect a project-level template to a view and URL.

1. What is a template?

Simple meaning

A Django template is usually an HTML file that Django uses to create the page shown in the browser.

Templates keep the presentation part separate from Python view code. Instead of building the whole HTML response inside Python, we keep the HTML in a template and render it.

HTML template
home.html
+
Django view
views.py
→
HTML response
Browser
Interview definition: A Django template is a presentation file, commonly HTML, that Django processes to generate the response sent to the browser.
2. How does a template work?
Browser requests URL
→
URLconf finds view
→
View calls render()
→
Django finds template
→
HTML response
from django.shortcuts import render

def home(request):
    return render(request, "home.html")

The render() shortcut loads the template, can receive context data, renders it, and returns an HTTP response.

Easy memory: URL → View → render() → Template → HTML Response → Browser
3. Template location types

Project-level templates

A shared templates/ folder is placed in the project root, commonly beside manage.py. Its location is added to TEMPLATES['DIRS'].

Useful for: shared or site-wide templates.

App-level templates

Templates can live inside a Django app. With APP_DIRS=True, Django can search installed apps for templates.

Useful for: templates that mainly belong to one app.

Learning note: This class intentionally creates views.py in the inner project package. In a real project, views are normally placed inside Django apps.
4. Project-level template setup - step by step
1

Create the template folder

Create templates in the outer project directory where manage.py is present.

myproject/\n├── manage.py\n├── myproject/\n└── templates/

Your supplied example uses template. That is also possible. The folder name and DIRS path must match. This document uses the common name templates.

2

Create the HTML file

Create home.html inside the template folder.

templates/
└── home.html
3

Configure settings.py

Add the template folder to TEMPLATES['DIRS'].

TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [BASE_DIR / 'templates'],
        'APP_DIRS': True,
        ...
    },
]
4

Create the view

For this learning example, put the view in the inner project package and import render.

from django.shortcuts import render

def home(request):
    return render(request, 'home.html')
5

Add the view to urls.py

from django.contrib import admin
from django.urls import path
from . import views

urlpatterns = [
    path('', views.home, name='home'),
    path('admin/', admin.site.urls),
]
6

Open the URL

When you visit the URL, Django calls the view, the view renders home.html, and the browser receives the HTML.

Final flow: / → views.home() → render(request, 'home.html') → templates/home.html → browser
5. Project structure
myproject/
│
├── manage.py
│
├── myproject/                 ← inner project package
│   ├── __init__.py
│   ├── settings.py
│   ├── urls.py
│   ├── asgi.py
│   └── wsgi.py
│
└── templates/                 ← project-level templates
    └── home.html
Remember: The outer folder contains manage.py and the project-level templates folder. The inner package contains project configuration such as settings.py and urls.py.
Real-project rule: Views normally belong to apps. The inner project package is mainly for project configuration.
6. Complete code

A. settings.py

import os

TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [BASE_DIR / 'templates'],
        'APP_DIRS': True,
        'OPTIONS': {
            'context_processors': [
                'django.template.context_processors.request',
                'django.contrib.auth.context_processors.auth',
                'django.contrib.messages.context_processors.messages',
            ],
        },
    },
]
Alternative syntax: os.path.join(BASE_DIR, 'templates') can also be used. If you use it, import os.

B. myproject/views.py

from django.shortcuts import render

def home(request):
    return render(request, 'home.html')

C. myproject/urls.py

from django.contrib import admin
from django.urls import path
from . import views

urlpatterns = [
    path('', views.home, name='home'),
    path('admin/', admin.site.urls),
]

7. App-level templates

In a real application, it is common to keep templates inside the app that owns the feature.

myproject/
├── manage.py
├── myproject/
│   ├── settings.py
│   └── urls.py
└── users/
    ├── views.py
    ├── urls.py
    └── templates/
        └── users/
            └── home.html
# users/views.py
from django.shortcuts import render

def home(request):
    return render(request, "users/home.html")
Best practice: Use project-level templates for shared pages and app-level templates for templates owned mainly by one app.
8. Common mistakes
1. Folder mismatch
templates/ is created but settings uses template.
2. Wrong DIRS
The project-level directory is not correctly added to DIRS.
3. Wrong template name
The path passed to render() does not match the discoverable template.
4. Wrong BASE_DIR assumption
The path built from BASE_DIR does not point to the folder you created.
5. APP_DIRS confusion
APP_DIRS=True helps with app-level template discovery; it does not replace project-level DIRS.
6. Views in wrong place
This lesson uses the inner project for learning. Real projects normally keep views in apps.
7. Duplicate names
Namespace app templates such as users/home.html to avoid collisions.
8. Template vs static
Templates generate HTML. Static files are CSS, JS, images, and other assets.
9. Interview tips
Q: What is a Django template?
A Django template is a presentation file, usually HTML, that Django processes to generate the response sent to the client.
Q: Project-level vs app-level templates?
Project-level templates are commonly configured through DIRS. App-level templates live inside an installed app and can be discovered when APP_DIRS=True.
Q: Why use render()?
render() provides a convenient way to load a template, pass context data if needed, render it, and return an HTTP response.
Q: Where should views normally be placed?
In a real Django project, views normally belong to Django apps. The inner project package is mainly for project configuration.
