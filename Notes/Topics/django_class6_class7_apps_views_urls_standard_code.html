Class 6 — Django Apps

Project vs App

In Django, we normally have one project that can contain many apps.

🏠 Django Project │ ├── 📝 Blog App ├── 🛒 Shop App ├── 👤 Accounts App └── 💬 Chat App

App = a feature or a group of related features.

For example, a shopping website might have apps for products, accounts, orders, and payments.

Easy memory: Project = the whole house. Apps = different rooms inside the house.
Why use multiple apps?

Apps keep code organized. Instead of putting every feature into one huge folder, each feature gets its own place.

Remember: One Django project can contain many Django apps.

1. How to Create a Django App

What does startapp mean?

startapp tells Django to create a new app folder with standard files for a feature.

Project ↓ startapp ↓ New app folder ↓ Feature-specific code

Run the command from the folder where manage.py is present, usually the outer project folder.

Command
python manage.py startapp appname

Example:

python manage.py startapp blog

Django creates a new blog folder.

2. Register the App

Add the app to INSTALLED_APPS

Creating the folder is not enough. Django also needs to know that the app belongs to the project.

Open the inner project's settings.py and add the app name to INSTALLED_APPS. 

INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',

    'blog',
]
Rule: If your app is named blog, add 'blog'.

3. Django App Folder Structure

Example: blog app
blog/ │ ├── __init__.py ├── admin.py ├── apps.py ├── migrations/ │ └── __init__.py ├── models.py ├── tests.py ├── views.py └── urls.py ← commonly created manually
Important: urls.py is commonly created manually inside the app. The standard startapp command does not create it.
What does each item do?
Item Simple explanation
migrations/ Stores files describing database structure changes for the app.
admin.py Used to register/configure models for Django's admin site.
apps.py Contains the configuration class for the Django app.
models.py Defines the app's data models.
tests.py A place to write automated tests.
views.py Contains views that receive requests and return responses.
urls.py Keeps URL routes for this specific app together.
__init__.py Python package initialization file.

Class 7 — Introduction to Views

What happens when a user enters a URL?
👤 User enters URL ↓ 📍 Django checks URL patterns ↓ 🔎 Finds matching route ↓ 👀 Calls connected View ↓ 📦 View creates Response ↓ 🌐 Response goes to user

A view is code that handles a request and returns a response.

Easy memory: URL tells Django where. View tells Django what to do.

4. What Is a View?

View definition

A Django view can be a function or a class that receives a request and returns a response.

Request → View → Response

HTTP response is information Django sends back to the browser, such as HTML or JSON.

Simple function-based view 
from django.http import HttpResponse

def home(request):
    return HttpResponse("Hello from Django!")
  • request contains information about the incoming request.
  • Django passes the request when it calls the view.
  • HttpResponse creates an HTTP response.
  • HttpResponse uses PascalCase.

5. URL Configuration — URLconf

What is URLconf?

URLconf means Django's URL configuration. It connects URL patterns to views.

URL pattern + Connected view ↓ Django knows which view to call

Think of it like a receptionist: “The user asked for /blog/. Which view should handle it?”

Main project urls.py using include()
blogs/view.py 
from django.shortcuts import render
from django.http import HttpResponse

# Create your views here.
def home(request):
    return HttpResponse("welcome to blog page")

def about(request):
    return HttpResponse("welcome to about page of blog")
blogs/urls.py 
from . import views
from django.urls import path

urlpatterns=[
    path("",views.home,name="home"),
    path("about/",views.about,name="about"),
]
myproject/urls.py 
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('blog.urls')),
]

include('blog.urls') tells Django to continue looking in blog/urls.py.

6. Function-Based View Import

Import the views module 
from django.contrib import admin
from django.urls import path
from blog import views

urlpatterns = [
    path('admin/', admin.site.urls),
    path('blog/', views.home, name='home'),
]

views.home means the home function from blog/views.py.

Import the function directly 
from django.contrib import admin
from django.urls import path
from blog.views import home

urlpatterns = [
    path('admin/', admin.site.urls),
    path('blog/', home, name='home'),
]
Both approaches work. They only differ in how the view is imported and referenced.

7. Class-Based View Import

Syntax

For a class-based view, use .as_view() in the URL pattern. 

from django.urls import path
from blog.views import HomeView

urlpatterns = [
    path('blog/', HomeView.as_view(), name='home'),
]
Remember: Use HomeView.as_view(), not just HomeView.
Example class view 
from django.http import HttpResponse
from django.views import View

class HomeView(View):
    def get(self, request):
        return HttpResponse("Hello from class-based view!")

The class extends Django's View class. The get() method handles a GET request.

8. Why Create urls.py Inside the App?

Keep feature routes together

With many apps, putting every route into one main urls.py can become difficult to manage.

Main project urls.py │ ├── include → blog/urls.py ├── include → shop/urls.py └── include → accounts/urls.py

This is similar to the router pattern often used in Node.js: each feature keeps its routes together, while the main URL configuration includes them.

Easy memory: Main urls.py = central traffic controller. App urls.py = routes for one feature.

9. Complete Class 6 + 7 Flow

From project creation to response
  1. Create the Django project.
  2. Create an app: python manage.py startapp blog.
  3. Register blog inside INSTALLED_APPS.
  4. Create a function or class inside blog/views.py.
  5. Create blog/urls.py and connect URLs to views.
  6. Include blog.urls from the main project's urls.py.
  7. Run the server and open the route in the browser.
Browser ↓ Main project urls.py ↓ include('blog.urls') ↓ blog/urls.py ↓ blog/views.py ↓ HttpResponse ↓ Browser
Interview Tips 💡
  • One project, many apps: apps represent features or related functionality.
  • View: a function or class that handles a request and returns a response.
  • URLconf: connects URL patterns to views.
  • Function import: from blog import views → views.home.
  • Direct import: from blog.views import home → home.
  • Class import: from blog.views import HomeView → HomeView.as_view().
  • Organization: keep each app's routes in its own urls.py and include them from the main URLconf.
