Object-Relational Mapping (ORM)

A simple guide to understand what ORM is, how it works, and why developers use it.

1. What is ORM?

ORM stands for Object-Relational Mapping.

ORM is a technique that allows us to work with a database using programming language objects instead of writing SQL queries for every operation.

Simple meaning: ORM acts like a translator between your application code and the database.
👨‍💻
Application

JavaScript, Python, Java, etc.

🔄
ORM

Converts objects into database operations.

🗄️
Database

MySQL, PostgreSQL, SQLite, etc.

Without ORM

You normally write SQL yourself:

SELECT * FROM users WHERE id = 10;
With ORM

You work with an object/model provided by the ORM:

const user = await User.findByPk(10);
Interview tip: Remember this sentence: “ORM maps database tables to objects in application code and allows developers to work with the database using programming-language objects.”

2. ORM Working Flow

Think of ORM as a bridge between your code and the database.

STEP 1
Write Code
Create, read, update, or delete an object.
→
STEP 2
ORM Receives It
The ORM understands your model operation.
→
STEP 3
SQL is Generated
The ORM creates the required SQL query.
→
STEP 4
Database
The database executes the SQL and returns data.
Example

Suppose your application needs all users.

const users = await User.findAll();

The ORM may translate this into SQL similar to:

SELECT * FROM users;
Important: The exact SQL generated depends on the ORM, database, model definition, filters, relationships, and other options.

3. Real-Life Example

Online Shopping Application 🛒

Imagine an online shopping website. The application has a User table in the database.

id name email
1Rahulrahul@example.com
2Anitaanita@example.com

Instead of directly writing SQL, the developer can use a User model.

const user = await User.findOne({ where: { email: "rahul@example.com" } });
What happens behind the scenes?
  1. Your code asks the User model to find a user.
  2. The ORM converts the request into SQL.
  3. The database executes the SQL.
  4. The ORM converts the database result back into an object.
  5. Your application uses that object.
Easy way to remember:
Object in code ↔ ORM ↔ Row in database

4. Advantages of ORM

1. Less SQL Code

Common database operations can be performed using models and methods instead of manually writing SQL each time.

2. Faster Development

Developers can use familiar programming-language objects and ORM methods to build database features quickly.

3. Easier to Maintain

Database-related logic can be organized around models, making large applications easier to manage.

4. Relationships

Many ORMs provide convenient ways to work with relationships such as one-to-one, one-to-many, and many-to-many.

5. Database Abstraction

Many ORMs provide a common programming interface across supported relational databases, although database-specific differences still matter.

6. Helpful Features

ORMS often provide features such as migrations, validation, transactions, query builders, and relationship handling.

Important interview point: ORM does not mean “SQL disappears.” SQL is still used by the database. The ORM mainly helps you work with the database at a higher level.

Quick Revision

  • ORM = Object-Relational Mapping
  • It connects application objects with database tables.
  • It translates ORM operations into database queries.
  • It reduces repetitive SQL code.
  • It can make development and maintenance easier.
  • Popular examples include Django ORM, Hibernate, Sequelize, and SQLAlchemy.
