1. What is Token Authentication in DRF?

Token Authentication is a simple, stateless authentication scheme provided by DRF's rest_framework.authtoken app. Each user is issued a unique, permanent token string. The client sends this token in the Authorization header on every request:

Authorization: Token 9944b09199c62bcf9418ad846dd0e4bbdfc6ee4

DRF's TokenAuthentication class looks up the token in the database (rest_framework.authtoken.models.Token), finds the associated user, and attaches it to request.user — no server-side session or cookies involved.

Unlike Session Authentication, Token Authentication is stateless from the cookie perspective and works great for mobile apps, SPAs, and third-party API clients since there's no CSRF concern — but the token itself must still be transmitted over HTTPS and stored securely on the client.
2. What are IsAdminUser and IsAuthenticated?
Permission Class Meaning Who can access?
IsAuthenticated Requires a valid authenticated user (any user) Any logged-in user
IsAdminUser Requires the user's is_staff flag to be True Staff / Admin users only
IsAdminUser checks request.user.is_staff — it does not require the Django is_superuser flag, just staff status.
3. Key Questions Answered
Does IsAdminUser mean only the Django superuser has access, or can other users access it too?
Not only the superuser. IsAdminUser grants access to any user with is_staff=True. A superuser automatically has is_staff=True, but so can regular staff accounts created via Django Admin without full superuser privileges. So it's "staff-level access", not strictly "superuser-only".
Does IsAuthenticated allow access only with a token — without a token can the user not access the view?
Correct. With TokenAuthentication + IsAuthenticated combined, a request must include a valid token in the Authorization header. Without it (or with an invalid one), DRF cannot resolve request.user to a real user, so the permission check fails and the view returns HTTP 401 Unauthorized.
Is is_staff=True returned when an admin user logs in, and is_staff=False for a non-admin user?
Yes, exactly. As shown in user_profile view, the response includes "is_staff": user.is_staff. An admin/staff account returns true; a regular (non-staff) account returns false. This field directly reflects the is_staff column on the Django User model.
If a non-admin user tries to access the admin_panel view, is access denied?
Yes. Since admin_panel is protected by permission_classes([IsAdminUser]), a non-staff authenticated user will still be rejected with HTTP 403 Forbidden — they're authenticated, but they don't have the required staff privilege.
4. When to Use Token Authentication
  • Mobile applications (iOS/Android) consuming a REST API
  • Single Page Applications (SPAs) that talk to a separate API domain
  • Third-party integrations / server-to-server API calls
  • When you want a stateless auth mechanism without CSRF handling
  • Consider JWT instead if you need token expiry, refresh tokens, or embedded claims — DRF's default token never expires by default

blog/views.py
from django.shortcuts import render

# Create your views here.
from rest_framework.decorators import api_view,authentication_classes,permission_classes
from rest_framework.response import Response
from rest_framework.permissions import IsAuthenticated,IsAdminUser
from rest_framework.authentication import TokenAuthentication
from rest_framework.authtoken.models import Token

#api only for  authenticated users
@api_view(['GET'])
@authentication_classes([TokenAuthentication])
@permission_classes([IsAuthenticated])
def user_profile(request):
    user=request.user
    return Response({
        "username": user.username,
        "email":user.email,
        "is_staff":user.is_staff
    })

#api only for admin users
@api_view(['GET'])
@authentication_classes([TokenAuthentication])
@permission_classes([IsAdminUser])
def admin_panel(request):
    return Response({"message":f'welcome to the admin panel,{request.user.username}'})
blog/signals.py
from django.conf import settings
from django.db.models.signals import post_save
from django.dispatch import receiver
from rest_framework.authtoken.models import Token

@receiver(post_save,sender= settings.AUTH_USER_MODEL)
def create_auth_token(sender,instance=None,created=False,**kwargs):
    if created:
        Token.objects.create(user=instance)

7. Interview Tips
1Know the difference: is_staff vs is_superuser.

is_staff just grants Django Admin access / passes IsAdminUser. is_superuser grants ALL permissions unconditionally. They are independent flags — a user can be staff without being a superuser.

2Explain how the token is generated automatically.

Be ready to describe the signals-based approach (post_save on the User model) used here to auto-create a Token for every new user, versus manually creating tokens.

3Common trick question:

"Can a non-superuser access an IsAdminUser view?" — Answer: Yes, if is_staff=True. IsAdminUser doesn't require superuser status, just staff status.

4Know the HTTP status code differences.

Missing/invalid token → 401 Unauthorized (authentication failed). Valid token but insufficient permission (e.g. non-staff hitting an admin view) → 403 Forbidden (authenticated but not permitted).

5Mention token security practices.

Tokens should be sent over HTTPS only, stored securely on the client (not in localStorage for sensitive apps if avoidable), and ideally rotated/invalidated on logout.
